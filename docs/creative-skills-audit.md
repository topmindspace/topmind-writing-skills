## 结论与证据范围

把创作经验组织成可选择、可观察、可比较的方法，比继续堆禁令更符合这套开放式写作技能的目标。本轮据此整改 8 个技能入口、共享参考、局部经验、脚本提示、文档与用例；不是用“必须出多稿”替换旧的固定流程。

方法启发来自用户提供的 [X 帖摘录](https://x.com/AlchainHust/status/2113650413170049529)。原帖访问返回 403，未读到全文；另实际阅读作者公开仓库 [huashu-design README](https://github.com/alchaincyf/huashu-design/blob/master/README.md) 对同一实验的说明。作者的小规模内部盲选提供了方向，不能证明本库已经改善质量。详细边界记录在 [创作方法与样张](../shared/references/creative-practice.md)。

同时使用本地 skill-creator 方法审查入口长度、按需阅读、用户意图与验证方式。已实际查看本仓封面总览：纯色巨字、摄影、留白、场景叙事并存；单一场景丰富度门槛与库内有效方向本身就不一致。

## 发现与整改

| 问题 | 原行为或风险 | 已做的修改 |
|---|---|---|
| 创作偏好变成硬约束 | 固定口吻、零 emoji、30 字首行、固定收尾、判断与配图配额 | 入口给读者目标、可选方向和判断方法；用户要求与作者样本优先 |
| 假定一种内容结构 | 长文统一过去—现在—未来，修改必须命中规则编号 | 支持评论、叙事、教程、研究；按授权修改结构和节奏 |
| 限定词被隐藏 | X 正文删除“厂商称”“约”“范围未确认” | 归因、精度、范围与发布状态留在正文，查证过程可另列 |
| 只有抽象风格名 | 多个方案可能只是同义改写或换色 | 新增完整写作样张、真实参考阅读方法、片段比较和匿名选择办法 |
| 视觉被统一场景化 | 每张角色动作、道具、装饰、背景层都有下限 | 字体、摄影、极简、抽象、原图、场景并列；配方按选中方向取用 |
| 自评分替代质量 | 85 分定稿、封面评分门槛 | 分数仅作诊断；以事实、读者理解、作者实际选择验证 |
| 工具反向约束用户 | 格式化删表情、拆链接；普通列表报错 | 默认保留，显式参数才转换；合理文字列表只提示 |
| 固定结构审计 | 必须写“不适用”和指定工作流标题 | 校验有效元数据与正文，路由质量用任务评测检查 |
| 来源被当成隐私 | 禁止第三方账号、参考链接、致谢出现 | 移除公开来源黑名单；独立密钥、私人路径与隐私扫描保留 |
| 简单任务流程膨胀 | 强制多稿、找图、询问配图、完整报告 | 单条任务直接完成，复杂探索才比较候选，报告按需要 |

保留的实际边界包括事实与引用准确、隐私与授权、恢复方式、文件不被意外覆盖、图片与文字映射、平台导出协议。具体平台旧经验以实际验证为准，未把审美选择当平台限制。

## 各技能的落点

| 技能 | 重点 |
|---|---|
| briefs | 信息直给、场景、取舍等角度；归因保真；无需固定图与收尾 |
| viral-posts | 保留类型库，允许表情、紧凑对话、类比、不同回复长度；去掉无数据的流量断言 |
| format | 纯排版保真，默认保留 URL、来源、表情与正反符号 |
| revise | 按目标选择深度，允许无 lint 命中的合理修改；不按修改比例直接判过度改稿 |
| wechat-post | 从当前进度接续；写作、排版、发布包按需求进入；词面分数不作定稿门槛 |
| x-article | 保留单源、图序与复制占位流程；已定稿只转换，不擅自再改写 |
| cover | 实际看样张，按主题选择不同视觉路径；标题准确优先，长标题可直接叠字 |
| poster | 布局与图形形式可选，保留渲染经验；纯文字海报不凑数据报告 |

长文平台的操作细节移至各自的 `references/platform-operations.md`。共享资源通过 manifest 同步到各技能，独立安装可用。

## 命令行为变化

```bash
# 默认保留原文表情、链接和来源
python3 scripts/format_text.py 原文.txt --mode duanzi --out 排版稿.txt

# 仅明确需要时使用转换参数
python3 scripts/format_text.py 原文.txt --mode short --separate-links --links-out 链接.txt
python3 scripts/format_text.py 原文.txt --mode duanzi --strip-emoji

# 默认列表与 URL 只提示；明确要求来源 / 链接另列时才启用 E10/E11
python3 scripts/lint_x_post.py 正文.txt
python3 scripts/lint_x_post.py 正文.txt --separate-links

# 封面标题：默认只给设计建议；主动选择严格模板才卡门禁
python3 scripts/title-engine.py --check spec.json
python3 scripts/title-engine.py --check --strict spec.json
```

从包含对应脚本的技能目录执行。过去依赖默认删表情、拆链接或标题静态检查失败码的调用方，需要显式补相应参数。`--strip-emoji` 会删去有语义的符号，使用后仍需人工确认。格式破损、图片占位、空输入和无效 JSON 等检查继续存在。

## 后续真实效果怎样比较

使用同一份素材、同一读者和相近输出预算，在独立干净上下文分别加载基线与当前技能；保存实际产物、实际读取参考记录、工具失败与成本。随机打乱版本标签，请作者选择更愿意使用的版本，并允许“无差别 / 各有用途”。

先看事实、归因、完整性是否保真，再比较理解成本、作者声音、方向差异和实际使用意愿。自由选择增加但最终稿更平，也算未达目标。反馈记录为“场景—选择—原因—例外—证据”，只在用户要求时写长期经验，不把一轮偏好固化成全局禁令。
