# 价值前置与可复用原件：让读者拿走就能用

原创教学与改稿案例总结；案例已做通用化脱敏处理，不可充当作者本次任务的亲历或实测事实。

## 一、核心机制：第一句给结果，正文留原件，结尾画边界

写经验、技巧、提示词、实测发现或规则变化时，读者最怕「先看三段背景介绍，最后只有一句空洞感悟」。高收藏短帖遵循四步结构：
1. **价值前置 + 保留钩子**：第一句直接把最反差的结果或核心建议抛出来（可用真问句形式），让人一眼知道有什么用。
2. **给可直接照做的原件（Takeaway Artifact）**：把英文提示词原句、终端命令或具体配置直接列出来，后面紧跟一句大白话中文翻译。
3. **说清适用场景**：一句话讲明什么时候最好用。
4. **画清负面边界（「什么时候别用」）**：明确告诉读者什么情况下千万别用——**读者的信任和收藏，往往就来自这条清醒的负面边界**。

## 二、改稿前后对照：提示词技巧帖（通用化案例）

### 改前（论文摘要腔 + 比喻升华收尾）
```text
最近有研究团队测试了大模型的编码习惯，发现模型默认倾向于最小化修改，哪怕原有代码结构很乱也会继续往上堆补丁。

研究人员尝试在系统提示词里加入了一句关于代码所有权的指令，结果模型主动重构代码的比例从 10% 大幅提升到了 50%，代码质量明显改善。

原来模型也一样，自己家的房子才舍得好好装修。大家平时写代码会加类似提示词吗？
```
**问题诊断**：第一段像论文背景综述；没有给出可直接复制的原句；最后一句用「自己家的房子才舍得装修」强行比喻升华 + 假互动提问，读完拿不走工具。

### 改后（结果钩子前置 + 原句交付 + 负面边界收尾）
```text
加一句提示词，模型主动重构代码的比例从 10% 涨到 50%？

有人测出来，在提示词里加上这句：
"Take full ownership of this codebase as its long-term maintainer."
（把这个代码库当成你长期维护的自己项目。）

它就不再只打补丁，会主动顺手清理坏味道、拆函数。适合重构老项目或从头搭模块。

不过如果只是想改个小 bug、动两行代码，别加这句，它会忍不住大动干戈...
```
**为什么有效**：
- 第一句直接用「一句提示词 → 10% 涨到 50%？」把性价比和好奇心拉满；
- 中间直接给英文原句 + 中文大意，读者复制就能用；
- 砍掉比喻升华，结尾停在「只想改小 bug 别加」的实用边界上，克制又专业。

## 三、经验观察帖的事实边界

当分享社区观察（如账号解封潮、额度变化、灰度测试）时：
- 可以给出清晰的观察结论与核查动作（「现在打开列表看一眼」）；
- **严禁代编作者没做过的亲历**（「我刚试着申诉成功了」），也**不凭空补未经核实的申诉方法或成功保证**；把「我看到 / 刚打开」留给作者本人定稿时按需补充。
