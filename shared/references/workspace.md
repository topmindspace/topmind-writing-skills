# workspace.md · 工作区规约与交付标准（长文）

> 适用：topmind-wechat-post / topmind-x-article。以下是 topmind 工作区的默认规约；其他用户可以用环境变量或 CLI 参数覆盖，技能本身不强制依赖特定目录结构。

1. **目录规约（默认）**：一篇长文一个文章文件夹 `<文章名>/`，里面只有一份源稿 `<文章名>.md`
   （外加 `images/`、`cover/`、`骨架.md`、`素材来源.md`、`raw/`、`out/`、`参考/`），放在工作区的长文类专题下（按类别**名称**找「长文」，
   兼容旧名「创作」「专题」；专题默认 `{当年}-公众号`），正式稿 HTML 交付到 role:delivery 类别
   （以工作区 `topmind.yaml` 的实际目录为准，例如 `88-输出/`）。编号与年份不写死。
   覆盖方式：`--base` 参数 > `TOPMIND_WECHAT_BASE` > `TOPMIND_WORKSPACE`（按名称发现类别）；
   都没有就报错要求传 `--base`，不猜惯例路径。详见各技能 SKILL.md 的「路径默认」节。
2. **云端备份**：文章创作结果默认在云端工作区按规约目录备份存档，方便找回、暂存。
3. **封面默认 2 版**：每篇长文默认提供至少 2 版不同风格的封面供用户选择。
4. **单源、按需派生**：长文默认只交付一份 Markdown（`<文章名>.md`，Obsidian 里直接能看）；
   用户要哪个平台的版本，再从它派生到 `out/`（X 长文 HTML / 纯文本 → `topmind-x-article`，
   公众号 HTML → `topmind-wechat-post`）。`out/` 是生成文件，不手改；改稿只改源稿，改完重新派生。
   短文、段子、回复不变：一段可复制纯文本，链接、原图另发。旧的「公众号稿 + 派生 X 稿」交付包只读兼容。
5. **多环境协作（可选）**：同一工作区在几个环境里改稿（比如一个主环境写稿、本地电脑做发布前修订）时，状态写进源稿 frontmatter，不靠文件时间猜：

   | 字段 | 写法 | 用途 |
   |---|---|---|
   | `updated_at` | ISO 8601，带时区，如 `2026-10-20T21:30:00+08:00` | 判断新旧的唯一依据 |
   | `updated_env` | 环境名，如 `主环境`、`本地` | 最后在哪改的 |
   | `updated_by` | `agent`、`手动`，或具体工具名 | 谁改的 |

   - 每次改稿更新这三项；`article_scaffold.py` 新建时自动写 `updated_at`，`--env` / `--by` 填另外两项。字段都可选，旧稿缺了不报；`check_article.py` 只在 `updated_at` 没有时区时给 H1 提示。
   - 新旧以同一份源稿的 `updated_at` 为准，文件修改时间和提交时间只作参考。两边都改过又分不清先后：不覆盖，旧的一份存进 `参考/` 交给作者定。
   - 提交信息带一致的前缀，写清状态变化，例：`[本地·手动] 发布前修订：改标题、补两张截图，草稿→定稿`。
   - 其他环境写的同主题稿件和素材放进 `参考/`：稿件命名 `参考-<环境>-<YYYYMMDD>.md`，素材文件名也带环境名，并在 `素材来源.md` 登记。参考稿永远不当源稿。
6. **公众号卡片和表格样式**：不用衬条（左侧色条、顶部 / 底部横线都不用），靠背景色调和大圆角区分层级；表格用浅色风格（表头浅蓝底 + 蓝色文字，无网格线，行间底部分隔线）；宽表转卡片时同样浅色、无衬条。
