# X 纯文本帖排版规则

> 适用：`topmind-briefs`、`topmind-viral-posts`、`topmind-format` 的 X 稿，`topmind-x-article` 的 `X发布稿.txt`（长文，可有文内链接），`topmind-wechat-post` 派生的 X 稿。公众号稿继续用 Markdown。
> X 长文富文本（`X长文.html`）以 `x-html-format.md` 为准。
> 配套文档：**交付与列表规约 `x-delivery-contract.md`（必读必守）**、emoji `emoji-system.md`、版式规律 `x-layout-patterns.md`。

## 一、不用 Markdown

X 普通帖不渲染 Markdown：`- ` `* ` `1. ` 列表、`#` 标题、`**加粗**`、`> 引用`、`[文字](链接)`、表格、`~~删除线~~`、反引号和代码围栏都会原样显示。
强调靠换行前置或「」。X 短文 / 段子的链接不进正文，另发（长文兜底稿可以直接贴 URL）。分点：**短文体可用 emoji 符号或「1）」「·」【小标题】等纯文本写法；段子体不加任何符号、完全不用 emoji**（见规约第二节）。

## 二、列表符号（短文体，任选一套，emoji 不强制）

| 用途 | 符号 | 说明 |
|---|---|---|
| 并列（默认） | 🔹 | 一级首选 |
| 二级 | ▫️ | 缩进两个半角空格；X 吞空格就用全角空格，仍不齐就压成一层 |
| 步骤 | 1️⃣ 2️⃣ 3️⃣ | 最多 9 条；也可 ① ②（≤20 条） |
| 对比 | ✅ / ❌ | 成对出现，唯一允许同层混用的组合 |
| 重点 | 📌 | 一帖最多标一条 |
| 纯文本并列 | · | 不想用 emoji 时的默认；别用半角 `- ` `* `（会被当 Markdown） |
| 纯文本步骤 | 1）2）3） | 全角括号；别用 `1.` `1)` |
| 分节 | 【小标题】 | 长帖分节，单独成行 |
| 严肃 / 英文帖 | • ▪ → | 事故、争议类不用 ✅ 🎉 |

规则：同层一个符号；一条一行（中文约 30 字内）；最多两层；一个列表 3–5 条、不超过 7 条，只有 2 条时写成两句；列表前一行「xx：」引导语。
短文体条目连续排（条目超过一行时条目间空一行）。段子体不用这些符号。

## 三、段落与留白

一段 1–3 行，段与段空一行，不出现连续两个空行（段子体的行间空行除外）。
钩子 / 标题、正文、列表、收尾、话题标签之间各空一行。长帖（约 500 字以上）用【小标题】单独成行分节。
段子体：一句一行，行与行之间都空一行，零 emoji（现成文字转段子体交给 `topmind-format`）。

## 四、来源与核实

1. 事实来自一手来源（官方公告、更新日志、论文、原帖、财报）；二手报道至少 2 个独立来源交叉确认，核实不了的承重事实删掉。
2. 厂商数字标「（厂商口径）」，未证实标「（传言）」，判断标「（推测）」。
3. **来源不进正文**：正文里只用文字点到出处（「官方博客称」「据论文」），来源 URL、原帖链接、来源行一律另发一条（名称｜发布时间｜URL），见规约第三节。
4. 资讯写具体日期，不写「近日」。

## 五、版式骨架

| 骨架 | 结构 | 适合 |
|---|---|---|
| 钩子 + 列表 | 钩子 → 「xx：」+ 3–5 条（· / 1）/ 🔹）→ 有观点的收尾 → 标签 | 更新、盘点、干货 |
| 步骤 | 痛点 → 1）–5）或 1️⃣–5️⃣ → 一句结论 → 标签 | 教程 |
| 对比 | 结论 → ✅ / ❌ 2–3 组 → 建议 → 标签 | 选型、评测 |
| 分节长帖 | 标题行（含核心事实）→ 导语 → 【小标题】× 3–5 → 收尾 → 标签 | 信息量大的资讯（需账号支持长帖） |

链接和图片不在骨架里，另发。thread：第 1 条放钩子和最关键事实，中间条目以「2/5」开头，最后一条放话题标签；每条单独交付，链接汇总另发（见规约）。

## 六、配图（原图优先）

1. 一手原图（官方图、原帖配图 / 截图、基准图、榜单实拍、论文原图）1–2 张当首图，不另配封面。
2. 没有原图：**先问用户要不要配图**，同意后才用 `topmind-cover`「X 短文封面」（16:9，1200×675），不擅自生图。
3. 纯文字段子可以不配图；不用 AI 图冒充原图；合计不超过 4 张。

## 七、公众号稿 → X 稿

只允许排版差异，数字、结论、条数、顺序不变；公众号里的文内链接移到另发的链接消息：

| 公众号稿 | X 稿 |
|---|---|
| `- 要点` / `  - 子要点` | `· 要点` 或 `🔹 要点` / `  ▫️ 子要点` |
| `1. 步骤` | `1）步骤` 或 `1️⃣ 步骤` |
| `## 小标题` | 单独一行文字，长帖用【小标题】 |
| `**重点**` | 去星号，前置或用「」 |
| `> 引用` | 「引文」+ 出处 |
| `[文字](url)` | 正文留「文字」，url 另发 |
| 表格 | 「项：值」列表行 |

示例（原创）：

```text
这次更新有三个变化：

🔹 响应时间：中位数从 2.4 秒降到 1.1 秒
🔹 价格：输入每百万 token 降 30%
🔹 限制：单次上下文仍是 128K
  ▫️ 超出部分需要分段处理

数字为厂商口径，实际延迟看地区和负载。
```

（官方更新日志的链接另发一条。）

## 八、检查工具

`python3 scripts/lint_x_post.py 正文.txt`（多条帖子用单独一行 `---` 分隔；段子加 `--duanzi`；长文兜底稿加 `--long`；`--fix --out 新文件` 自动把 Markdown 改成 X 写法，加 `--style plain` 改成「·」「1）」）。

| 代码 | 含义 |
|---|---|
| E1–E9 | Markdown 列表 / 有序列表 / 标题 / 加粗 / 引用 / 链接 / 表格 / 代码围栏 / 删除线（错误） |
| E10–E12 | 正文有 URL / 来源行 / 配图说明或图片占位（错误；`--long` 不查） |
| W1–W7 | 反引号、列表超两层、同层混用符号、列表超 7 条、话题标签不在末行、标签超 3 个、超字数 |
| W8–W13 | 点缀表情过多、AI 套话（含排比、「不仅…更…」、空泛形容）、首行过长不像钩子、连续空行、正文混入说明 / 内部标签、段子体出现 emoji（`--duanzi`） |
