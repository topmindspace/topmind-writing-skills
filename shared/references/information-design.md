# information-design.md · 信息设计（第 1 层）

> 适用：全部写作、排版、改稿、长图技能。建立在 `social-writing-principles.md`（第 0 层）上：先想清楚传达什么，再决定用什么形式传达。
> 本文件给的是判断方法和参考线，不是门槛。脚本里对应的提示是 `I1`–`I8`（见文末），只提示、不判卷。

## 一、先写骨架，再写文字

长文动笔前先写骨架；短文在脑子里过一遍也行。骨架回答四件事：

1. **主要信息**：读者看完该知道什么（一两句）。
2. **读者**：谁、已经知道什么、为什么会看。
3. **每节**：要点、形式、图表计划、预估字数。
4. **篇幅预算**：全文大概多少字、几张图、几个表或列表。

模板（长文可以直接写在源稿最前面的注释里，`article_scaffold.py` 会生成）：

```markdown
<!-- 骨架
主要信息：
读者：
篇幅：约 ____ 字，__ 张图，__ 个表 / 列表
| 节 | 要点 | 形式 | 图表计划 | 字数 |
|---|---|---|---|---|
| 开头 | | | | |
-->
```

**为什么**：形式不在骨架里定下来，默认就会写成段落。骨架里写了「表格」「时间线图」，写的时候就不会把它们写成三段散文。

## 二、内容 → 形式决策表

先判断内容的形状，再选形式。

| 内容的形状 | 首选形式 | 次选 | X 纯文本里怎么表现 |
|---|---|---|---|
| 一个结论 / 判断 | 一句话，放段首或首段 | — | 首行 |
| 3 个以上并列要点 | 无序列表 | 短段落 | 「·」分行 |
| 步骤、流程、先后顺序 | 有序列表；复杂的画流程图 | 时间线图 | 「1）2）」分行 |
| 多个对象比较多个维度 | 表格 | 分行对照 | 分行「A：…」 |
| 改前 / 改后、方案 A / B | 两列表格或对照块 | 两个短段 | 「改前：」「改后：」各一行 |
| 随时间变化的数据 | 折线图 / 柱图（原图优先） | 关键数字 + 一句解读 | 关键数字一行，原图另发 |
| 排名、占比、构成 | 原榜单截图；条形图、堆叠图 | 表格 | 前几名一行一个 |
| 时间线 | 一句话 + 时间线图 | 有序列表 | 「· 日期：事件」 |
| 产品界面、原帖、官方说法 | 原图 / 截图 | 引用块 | 截图另发 |
| 一组关键数字 | 「数字一览」列表 | 表格 | 每行一个数字 |
| 因果、取舍、判断理由 | 段落（这是文字的主场） | — | 短句 |
| 故事、场景、段子 | 段落 / 一句一行 | — | 一句一行 |

- **例子**：「我们试了三种同步方案，A 快但贵，B 便宜但会冲突，C 两者折中但要自己部署」→ 一张三行表（方案 / 速度 / 价格 / 代价），表下一句判断「个人用户选 C」。
- 自制图：一张图只说一件事，图的标题直接写结论（「第三周开始反超」），去掉不带信息的网格线和装饰；能用原图就不自制。

## 三、篇幅和密度

参考线（超过就回头看一眼，不是硬性上限）：

| 项 | 参考 |
|---|---|
| 短文 | 300–800 字；X 短文首行约 30 字内 |
| 长文 | 1500–2500 字；超过 3000 字要有理由（教程、深度研究） |
| 段落 | 2–3 句，手机上不超过 5 行（约 110 字） |
| 连续纯文字 | 不超过 3 块；再多就插图、表或列表 |
| 图表密度 | 长文每 500–800 字一个非段落元素（图、表、列表） |
| 每一节 | 至少一个非段落元素；判断类小节可以例外 |

- **篇幅按读者价值分配**：读者最想要的（判断、新东西）给最多篇幅，背景和过去最少。长文的「过去」一节，一句话加一张图通常就够。
- **例子**：一篇 2000 字的趋势长文，过去 200 字、现在 700 字（列表 + 图）、未来判断 800 字、收尾 100 字。

## 四、去啰嗦的判断法

逐段问一遍：

1. **删句**：删掉这句，读者少知道什么？
2. **看图**：这句是不是在描述旁边那张图？
3. **已知**：读者在上文、原帖、标题里已经知道了吗？
4. **自明**：不说读者也会这么想吗？
5. **合并**：相邻两段是不是在说同一件事？
6. **形式**：这段是不是一张表或一个列表被写成了段落？

- **例子**：「这次更新很重要。它带来了三个变化。第一个变化是……」→ 前两句删掉，三个变化直接写成列表。

## 五、X 和公众号的形式差异

| 项 | 公众号 / Markdown 长文 | X 长文 | X 短文 / 段子 / 回复 |
|---|---|---|---|
| 表格 | 可以用 | 不渲染：转成分行对照，或做成图 | 不用，分行写 |
| 列表 | Markdown 列表 | 列表可用 | 「·」「1）」分行，段子不加符号 |
| 图 | 紧跟它证明的文字 | 同左 | 原图另发，正文不写配图说明 |
| 链接 | 重要的一两个挂正文，其余文末 | 同左 | 另发 |

## 六、和脚本的关系

`scripts/info_design_hints.py`（`de_ai_lint.py`、`lint-wechat.py`、`revise_check.py` 也会调用）给出 `I` 前缀的提示，和去 AI 味的 W / H 分开显示。它们永远不进 `--strict`，也不是交付门槛：

| 码 | 提示什么 |
|---|---|
| I1 | 连续纯文字块过多 |
| I2 | 图、表、列表太少（按字数算） |
| I3 | 一句里并列项多，可以转列表 |
| I4 | 连着几组「改前 / 改后」「A：/ B：」对照，可以转表格 |
| I5 | 相邻段落重复表达，或段首复读小标题 |
| I6 | 首段太长或没有交底 |
| I7 | 某一节很长却全是段落 |
| I8 | 超出骨架里写的篇幅预算 |

随笔、故事类文章（frontmatter 写 `type: essay`）不提示 I1、I2、I7。
