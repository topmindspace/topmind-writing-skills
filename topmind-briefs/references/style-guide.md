# 风格指南 · 干货短文

目标：读者划过去，3 秒内抓住那个数字/结论，心想"这篇有料"。

## 三原则

**短**：一件事讲完就停。X 版每条 280 字符内（超了拆 thread，最多 3 条）；公众号版约 300–800 字
（与 SKILL.md、`platform-specs.md` 同一口径）。
**干**：每个字都承载信息。删掉所有"众所周知""值得一提的是"。
**准**：数字有来源，判断有依据。不确定的写"据 X 报道"，不编。

## 开头：四种起手

- 数据榜单型："[反直觉判断一句]。On [基准], [最扎眼数字]。"
- 榜单速报型："Just in: [模型] now ranks #[名次] on [榜单] with [分数]."
- 论文解读型："[判断句]。New idea: [X 的思路一句]"
- 机制讲解型："How [X] works, step by step. [痛点一句]"

## 正文：合理分段、合理列表

并列信息 3 条以上用列表，2 条写成两句。X 版分点用 emoji 或「1）」「·」【小标题】（emoji 不强制，禁用 `- ` `1. `），骨架与交付见 [platform-specs.md](platform-specs.md) 和 [x-delivery-contract.md](x-delivery-contract.md)；公众号版用 Markdown 列表，两版内容一致。

## 禁止清单

- 禁止"首先、其次、最后""总而言之""总的来说""值得一提的是""值得注意的是""不仅…更…"
- 禁止三连排比（"更快、更强、更智能"）和过度对称（每条列表一样长、一样句式）
- 完整去 AI 味 + 吸引力清单见 [writing-principles.md](writing-principles.md) 第五点五节
- 禁止"赋能""抓手""闭环""底层逻辑"
- 禁止铺垫三段再说结论
- 禁止没有数据的形容词："大幅提升""显著改善"（改成具体数字）
- 禁止感叹号连用
- 禁止"家人们""老铁"式直播腔
- 禁止正确的废话

## 鼓励

- 数字代替形容词："快 3 倍"不说"大幅提升"
- 对比代替孤立数字："58 分，比 Opus 5.5 高 2 分"不说"58 分，很高"
- 有观点的收尾：一句判断、建议或具体问题——只写一句，不复述、不升华
- X 版来源链接另发，不进正文；正文里用「官方称」「据论文」点到出处
- 允许短句和碎片化断句，像人说话一样写，不追求完整长句（去AI味）
- 标题可以冲，但正文必须有真东西支撑，不做空转标题党

## 自检三问

1. 删掉一半字，核心结论还在吗？（在→删）
2. 每个数字都能在另发的链接里找到一手出处吗？（不能→删或补来源）
3. 不看图，文字本身成立吗？不看文字，图本身有信息吗？（都成立→图和文各司其职）
