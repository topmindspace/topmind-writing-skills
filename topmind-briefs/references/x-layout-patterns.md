# X 短文版式规律

> 适用：`topmind-briefs`（短文）、`topmind-format`（格式化）、`topmind-viral-posts`（段子 / 短帖）的 X 纯文本稿。
> 本文只记**版式规律**，全部用我们自己的话描述。emoji 一律按 `emoji-system.md` 的 TopMind 体系取。

## 六种版式骨架

| # | 体裁 | 一句话版式特征 |
|---|---|---|
| A | 中文测评速报 | 标题行带结论 → 「证据拆解：」→ 1️⃣–5️⃣ 证据 → 一句评价 → 一句金句 → 末行话题标签 |
| B | 英文视频导流 | 两行短句钩子，各自成段 → 「In this video:」+ 3 条短条目 → 末行「Full breakdown: 链接」 |
| C | 英文清单体 | 一句引子 → 13 条 • 列表，每条一行，长短交错，无收尾 |
| D | 中文工具推荐 | 痛点场景开头 → 是什么 → 技术来源 → 链接单独一段 → 用法举例 → 隐私说明 → 一句推荐收尾；全程无 emoji、无列表 |
| E | 中文作品拆解 | 情绪 emoji + 标题 → 「关键细节拆解：」→ 7 条 🔸 + 1 条 🔹 收束，条目间空行 → 一句总结 → 话题标签 → 末行链接 |
| F | 中文分节资讯短文 | 标题行写全核心事实（谁/何时/价格）→ 导语段 → 【小标题】分节 × 5 → 每节 1–4 个短段 → 无 emoji、无话题标签 |

## 一、开头钩子

1. **标题行就给结论**：A、F 的第一行把「是什么 + 最扎眼的事实」写全（F 连价格都写进标题），读者只看第一行也拿到信息。
2. **场景钩子**：D 用一个人人遇到过的痛点场景开头（想不起文件名），第二段才说产品——适合工具推荐。
3. **两句短钩**：B 用两句各成一段的短句（判断 + 对比），英文帖常见。
4. 钩子行最多 1 个情绪或标题 emoji（A、E 在行首各 1 个）；F、D 完全不用也照样清楚。

TopMind 写法：短文首行 = 可选的标题 emoji（按关键词对照表，0–1 个）+ 带结论的标题；段子首行 = 钩子句，不加任何 emoji。

## 二、分段长度与空行节奏

1. **一段一个意思**：D、F 每段 1–3 句，中文约 40–90 字；段与段之间一定空一行。
2. **标题、引导语、列表、收尾、标签之间各空一行**；列表内部一般不空行（A、C）。
3. **条目本身很长（超过一行）时，条目之间空一行**（E）——否则手机上挤成一团。
4. 较长的短文（F）用【小标题】单独一行分节，节与节之间空一行；小标题后紧跟正文，不再空两行。
5. 不出现连续两个以上空行（段子体的行间空行是唯一例外）。

## 三、列表写法

1. **引导语 + 冒号**：「证据拆解：」「关键细节拆解：」「In this video:」——先告诉读者下面是什么。
2. **符号按用途选**：有先后 / 证据链用 1️⃣ 2️⃣ 3️⃣（A）；并列要点用 🔹 或 •（C、E）；一帖一套。
3. **条目格式**：`关键词：说明` 或 一句完整短句；条目开头就是关键词（E 的「商店街：」「夜景氛围：」）。
4. **数量**：短帖 3–5 条最舒服（A 5 条、B 3 条）；C 的 13 条清单体只适合纯吐槽/盘点，干货短文不超过 7 条。
5. **收束条**：E 用一个不同符号标出最后一条「交互」作为收束——TopMind 里改用 📌 标最关键的一条，不在同层换符号。
6. 列表后接**一句总结**（A、E）把读者拉回结论，再接标签。

## 四、emoji 用法

1. 常见写法里 emoji 只出现在三个位置：**标题行首、列表行首、（偶尔）收尾行**；正文段中间都不插。
2. 信息密度越高、emoji 越少：F、D 零 emoji 依然好读，靠的是空行和【小标题】。
3. 不连用、不堆叠；🔥 😍 这类情绪 emoji 属于个人风格，**TopMind 不照搬**——标题 emoji 只按关键词对照表取，人设点缀用 🐔 🐱 🌱 等（见 `emoji-system.md`）。
4. **段子体完全不用 emoji**：像 D 那样只靠一句一行和空行；分点不加符号。

## 五、中英混排

1. **中文帖里的英文专名保留原文**（Tokenizer、Three.js、EmbeddingGemma、API），首次出现可加中文解释（F：「token（模型处理文字的基本单位）」）。
2. **中英文之间加半角空格**（D、F 的写法：「Mac 上的本地搜索工具」「7.4 亿参数」）；数字与中文单位之间不加空格亦可，但一帖内统一。
3. 中文标点用全角（，。：「」），英文句子内用半角；不在中文句中夹英文标点。
4. 英文帖（B、C）短句、一行一意，列表符号用 • 或 >，不用中文标点。

## 六、链接与话题标签位置

1. 常见写法是把链接单独成段（如「GitHub：URL」「Full breakdown: URL」）。**TopMind 不照搬**：X 短文 / 段子的正文里不放任何 URL 和来源行，链接整理成单独一条另发（见 `x-delivery-contract.md` 第三节）；正文自足，不写查证过程；需要点出处时一句带过（「官方博客写了」），口径提醒放交付说明（core-voice V39）。
2. **话题标签放末行**（A）；E 在标签后又放链接、F 不放标签——TopMind 统一为：段子和短文默认不带话题标签；要带最多 2 个（宽泛词 + 主题词），放正文最后一行；关系帖 1–3 个；不堆 6–10 个（A、E 的堆标签不学）。

## 七、结尾

1. **短文默认事实讲完就停**，不写收尾句；需要时用「...」留口子（`core-voice.md` V10）。
2. 确实需要一句时（推荐类、教程类），用短句 + 态度或一个行动理由（「装一个能省不少事」），单独成段、不超过一行，不做总结复述；不用套路互动问句，作者真拿不准的问题可以留（core-voice V34）。
3. 收尾行可选放 1 个人设点缀（🌱 🐾），不放也行；严肃资讯和段子不放。

## 八、一页速查（写完对照）

- 首行一句简单的话题陈述，有结论或最扎眼的事实；标题 emoji 可选，0–1 个且对得上关键词
- 段落 1–3 句，段间空一行；长条目之间空一行
- 列表前有「xx：」引导语；一帖一套符号（默认「·」，行多用「1）」，短列表才用 emoji）；3–5 条
- 事实讲完就停，不硬加收尾句
- 英文专名保留，中英之间空格
- 正文无 URL、无来源行；话题标签在最后一行；链接、图片另发
- 无 Markdown 符号（`- ` `* ` `#` `**` `>` `[]()` 反引号）
