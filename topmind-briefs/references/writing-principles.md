# 发文铁律：精炼客观 + 素材优先 + 研究深度

> 适用于 topmind-briefs / topmind-x-article / topmind-wechat-post / topmind-viral-posts / topmind-revise（段子按第五、五点五节去 AI 味，长文另过五点六节，其余以该技能的写作铁律为准）。
> 标题、开头、收尾、数字、引用、回复、段子等场景规则统一见 `core-voice.md`（V01–V33）；本文件和它冲突时，以 `core-voice.md` 为准。
> 触发技能时默认执行，无需用户每次声明。

## 一、默认写作模式：精炼客观

1. **文字精炼**：能一句话说清的不用两句；删一切"正确的废话"。
2. **陈述客观事实**：只写可核实的事；厂商数字标"厂商口径"；无法核实就删。
3. **不泛化**：不从单个案例跳到"行业趋势"；不从一次测试跳到"彻底改变"。
4. **不主观判断**：不写"令人惊艳""颠覆性""必看"这类无法验证的形容词。
   让事实自己说话。
5. **标题不反问、不说教**：标题写清讲什么。热点标题可以带人物和一个有悬念的问句
   （例：「某商店下架某插件，作者要自己做一个？」）；判断不确定时，不靠标题问号表达，
   在正文里用「现在看起来」「大概率」写清强度（`core-voice.md` V01、V08）。

## 二、素材优先原则

1. **信息收集**：基于用户要求，做全面的信息和素材收集、整理、交叉比对核实。
2. **原图优先**：官方图表、第三方榜单、数据表格——尽量用原图，不手绘仿制。
3. **图说事实**：能用素材图片传达的意思，文字就少写。图承担数据，正文只解读。
   看图即知的事实（数字、趋势、结构）正文不再复述一遍，只写图看不出的解读和判断。
4. **素材排序**：官方产品截图 > 官方基准图 > 第三方榜单截图 > 权威媒体图表 > 自制图表。
   自制图只用于时间线、价格对比、总结盘点（无法找到原图时），并标「自制」和数据来源。
   写稿前先找图、记来源，流程见 `image-sourcing.md`。
5. **配图丰富度（主动挖掘）**：不要等"有图就用"，要主动找图——论文原图/图表、
   工具截图、评测基准原图、关键帖子截图、产品界面实拍。有信息量的段落尽量配图，
   装饰图一律不要。目标：读者看图能跟上 70% 的论证，文字负责剩下的 30%（判断与连接）。

## 二点五、可视化优先（写作铁律）

> 能用可视化传达的，不用文字啰嗦。这是 X 和公众号共同的内容要求。

1. **表格 > 段落**：对比类内容用简单表格，不写大段文字。
2. **列表 > 段落**：并列要点用列表，不写成长段。公众号稿用 Markdown 列表；X 纯文本帖不渲染 Markdown，用 emoji 项目符号（🔹 / 1️⃣，规则见 `x-post-format.md`）。
3. **"概要 + 列表"**：信息密集的节，先给一句概要（这节的结论），再用列表展开论据。
   不写长段论述；非写不可的长段，拆成多个短段或转成"概要+列表"。
4. **图表 > 描述**：数据趋势用图表，图片用素材原图。
5. **卡片样式**：MD3 优雅风——不用任何衬条（左侧色条、顶部/底部横向线一律不用）；
   靠背景色调（tonal）+ 大圆角区分层级。表格用浅色风格：表头浅蓝底 + 蓝色文字，
   无网格线，行间用底部分隔线；宽表转卡片时同样浅色、无衬条、标题用蓝色强调。
6. **文字密度**：每段 ≤110 字；列表项 ≤70 字；健康密度 300-450 字/图。

## 三、研究探讨模式（用户做研究/思考时）

当用户给出主题 seed、问题、思考、启发、线索，要求探讨分析时：

1. **充分收集**：信息收集、整理分析、检索比对，一个都不能少。
2. **客观为基**：所有论述建立在核实过的事实上。
3. **主观有度**：可以有针对性的主观论述、论点、判断、分析——
   但必须：不肤浅、洞察深入、严谨、有思考、有全面性/系统性、
   角度有特点、有判断力。
4. **留白提问**：可以提出合理的问题留待后续交流或跟进；可以合理挑战既有观点。
5. **论文扩展**：有条件时，寻求高质量论文、研究报告，进一步分析扩展。

## 四、禁止清单

- ❌ 泛化扩展：从个案跳到全行业
- ❌ 主观陈述：无法验证的形容词和判断
- ❌ 编造数据：任何未经核实的数字
- ❌ 套话：正确的废话、社交垫词
- ❌ 浅层分析：只复述事实不给洞察（研究模式下）

## 五、措辞偏好

用户对"AI 味"的判断标准：不是词汇黑名单，而是**空洞断言、伪简洁、评论腔**。以下是改稿中确立的实例：

- **不用噱头式导语**：❌"两条帖子，一个判断" → ✅"看他们的互动讨论有了这样的感觉："。平实描述代替 clever framing。
- **不用"一句话"式伪简洁**：→ ✅"简单来说"/"简单总结"，或干脆删掉。
- **断言要有依据**："毫无疑问""归根结底""真正的"不是禁词，后面跟着判断和依据就能用；空着用才删（`core-voice.md` V08、V20）。
- **判断强度**：已经 > 大概率 / 预计 > 照现在的速度，多半 > 现在看起来 > 可能。不写"我认为"，不必反复强调"我"。
- **"全文的题眼"→"原话中最关键的一句"**：不搞评论腔。
- **"同一份报告"→"报告中 XXX"**：指代词累赘，直接说。
- **"坑"→"挑战"/"问题"**："七个坑"改"七个挑战"。
- **梗看读者**：圈内梗可以进长文和标题；读者看不懂的自嗨梗才删（V19）。
- **不堆强烈描述词**：不堆"最""极""颠覆"；"重磅"只给真重磅（V20）。
- **精炼不等于硬砍字**：❌"谱系很老" → ✅"谱系可以追溯很早之前"；❌"发版最密" → ✅"发版最密集的一个月"（V32）。

总原则：**断言有依据，简洁不取巧，评论腔删掉**。用户改过的说法就是标准答案，下次同类位置直接用改后版。

## 五点五、去 AI 味 + 吸引力清单（成稿后逐条过；X 短文、段子必过）

AI 味多数来自句式，不是单个词。下面每一类都给出改法，改完再读一遍，读着像人说话才算过。

| 类型 | 典型写法 | 改法 |
|---|---|---|
| 套话开头 | 「在当今 AI 飞速发展的时代」「随着……的发展」「众所周知」 | 删掉，直接从事实或问题开始 |
| 机械连接 | 「首先 / 其次 / 最后」「综上所述」「总而言之」「总的来说」「总体而言」 | 用列表或序号承载顺序；结尾不做总结复述 |
| 假强调 | 「值得注意的是」「值得一提的是」「划重点」 | 删掉，把要强调的内容挪到段首 |
| 二元反转 | 「不是 A，而是 B」「真正的 X 从来不是……」 | 优先改成「其实是 B」（V09） |
| 递进套句 | 「不仅……更……」「不仅……还……」「既……又……」 | 拆成两句，各说一件事，或只留更重要的那件 |
| 过度对称 | 每段一样长、每条列表一样的句式和字数、「一方面……另一方面……」 | 长短交错；列表条目按信息量写，不凑齐 |
| 空洞断言 | 「意义重大」；后面没有内容的「毫无疑问」「不可否认」 | 删掉，用一个事实撑住判断；后面有判断和依据就留（V08） |
| 三连排比 | 「更快、更强、更智能」三词一组 | 只留有数据支撑的那一个，配上数字 |
| 空泛形容 | 「颠覆性」「革命性」「惊艳」「炸裂」「全方位」「一站式」「无缝」「划时代」 | 换成可核实的事实：参数、价格、日期、对比；「重磅」只给真重磅（V20） |
| 升华结尾 | 「这或许就是未来」「让我们拭目以待」「开启新篇章」 | 停在一个判断上；长文可以「总结来说 + 结论 + 一句口语收尾（拭目以待吧）」（V10） |
| 标题党词 | 「建议收藏」「干货满满」 | 标题写清讲什么；「一文读懂」用在摘要里可以（V04） |
| 破折号与冒号堆叠 | 一段里三四个「——」「：」 | 一段最多一个，其余拆成短句 |
| 表情堆砌 | 🔥🚀💯 连用，每行都有表情 | 短文列表默认「·」，emoji 只给短列表，用就按 `emoji-system.md`；段子零 emoji（V25、V26） |
| 翻译腔 | 「进行了一个优化」「做出了改进」「基于……的考虑」 | 「优化了」「改了」，动词直接上 |

**吸引力要求**（去掉 AI 味之后，还要让人想读完）：

1. **首行是一句简单的话题陈述**：约 30 字以内，给结论或最扎眼的事实；不用设问钩子；真里程碑把「历史第一」放句首（V05）。
2. **具体数字和场景**：「补全延迟 200ms 以内」胜过「大幅提速」；「写小脚本的人免费额度够用」胜过「适合多种用户」。
3. **说人话**：口头会怎么说就怎么写，短句可以，碎句也可以；不用「进行了一个」「做出了改进」。
4. **收尾轻**：短文事实讲完就停；长文最后一句给判断，换个角度说（V10）；默认不以问句结尾，不复述、不升华。
5. **信源诚实**：厂商数字写「官方称」；有一手信源但未完全确认的热点可以直陈加「？！」，纯传闻不发（V22）；吸引力不能靠夸大事实换。

自查方法：

1. **朗读测试**：读出来拗口、像念稿，就改成口头会说的话。
2. **删句测试**：删掉一句不影响信息，这句就删。
3. **替换测试**：把产品名换成另一个产品，句子照样成立，说明它是空话，换成只属于这件事的细节。
4. **工具**：完整规则表见 `de-ai-rules.md`（中英文结构模式、改写边界），场景规则见 `core-voice.md`。X 稿跑 `scripts/lint_x_post.py`，Markdown 稿跑 `scripts/de_ai_lint.py`：W 警告每条要有结论，H 提示只供判断，不要求改；再逐段人工过「人工」类模式。

## 五点六、长文改稿：说人话、按读者写、图先于字（2026-10 起）

用户对长文的三条硬要求：**文字少、像人说的、有原图**。成稿前逐条过。

**1. 公式化标签改成平实说法**

| 不要写 | 改成 |
|---|---|
| 「xx 三个词」「用三个词概括」 | 「简单总结」，或直接把三点列出来 |
| 「xx 一句话」「一句话说清」 | 「简单说」「简单总结」，或删掉直接说结论 |
| 「xx 五个分支」「六种活法」 | 「主要 5 个方向」「主要 5 类」 |
| 「就三件事：A、B、C」 | 「有三大特征」「主要三点」 |
| 「不是 A，而是 B」「从来不是」 | 优先改成「其实是 B」；「真正的」看场景可用（V09、V20） |
| 「起了个大早，赶了个晚集」这类俗语收尾 | 删掉，换成一句有数字的事实 |

**2. 按读者水平写**

- 读者有基础：不解释大家都懂的概念（什么是 agent、什么是长期记忆），直接给事实和判断。
- 读者分三档：大众文一句定义；专业技术长文给全称、出处和准确定义（V18）。
- **过去**：最好就是一句话加一张时间线图，只留后面论证要用的事实。
- **现在**：简单汇总加一句分析，用列表或图，不逐个产品写一段。
- **未来**：写真判断，用「预计」「大概率」直接说，不必强调「我」；判断后面跟一条支撑它的事实。厂商数字标「厂商口径 / 官方称」，查不到一手来源的直接删。

**3. 图先于字**

- 能用原图说明的，文字只留一句引导，不复述图里的数字。
- 原图优先级：官方公告或产品页截图 > 原始 X 帖截图（官方 embed 渲染）> 官方文书（诉状、判决、论文原图）> 第三方数据图 > 自制图。
- 自制图只在找不到原图、且数据有出处时用，图内写明数据来源和「图为自制」。
- 每张图在本地私有信源清单里记一条来源 URL 和读取日期；信源清单不进公开仓库。
- 多个同类官方图（如同期发布的一组产品）拼成一张带日期标注的拼版，避免连续刷屏。

**4. 不写大段文字**

- 一段 2–3 句、单段不超过约 110 字（W14 / H10）；超过就拆短段，或改成「一句概要 + 列表」。
- 一节里不要连着三四段纯文字，中间插图或列表。
- 用分号串起来的长句（「A；B；C；D」）一律拆成列表。

**5. 改稿流程**（装了 topmind-revise 就交给它；没装按 `revision-workflow.md` 手动走；找图与信源清单见 `image-sourcing.md`）

1. 先审逻辑：结论是否在开头、过去 / 现在 / 未来比例是否对（过去最短，未来最有观点）。
2. 承重事实逐条回一手来源；上一版文本里的数字最不可信，全部重核。
3. 找原图、下载、记来源，再按图删字。
4. 去 AI 味：按 `de-ai-rules.md` 逐条过（先守改写边界），再按本文第五、五点五、五点六节通读一遍，只改表达，不增删事实。
5. 跑 `de_ai_lint.py`（Markdown 稿）或 `lint_x_post.py --long`：W 每条有结论，H 只供判断；用 `count_words.py` 对比改稿前后字数。变短是删冗余的结果，不是目标：直白但啰嗦的句子只删多余部分。

## 六、工作区规约与交付标准

> 以下为 topmind 工作区默认规约；其他用户可通过环境变量或 CLI 参数覆盖，
> 技能本身不强制依赖特定目录结构。

1. **目录规约（默认）**：公众号+X 创作包放在工作区的长文类专题下（按类别**名称**找「长文」，
   兼容旧名「创作」「专题」；专题默认 `{当年}-公众号`），正式稿 HTML 交付到 role:delivery 类别
   （以工作区 `topmind.yaml` 的实际目录为准，例如 `88-输出/`）。编号与年份不写死。
   覆盖方式：`--base` 参数 > `TOPMIND_WECHAT_BASE` > `TOPMIND_WORKSPACE`（按名称发现类别）；
   都没有就报错要求传 `--base`，不猜惯例路径。详见各技能 SKILL.md 的"路径默认"节。
2. **云端备份**：所有文章创作结果默认在云端工作区按规约格式目录备份存档，
   方便找回/暂存。
3. **封面默认 2 版**：每篇长文默认提供至少 2 版不同风格 cover 供用户选择。
4. **双平台同步**：默认 X + 公众号双版，不分长短文。

## 七、研究深度要求（用户给定主题）

1. **全面调研**：外部调研、分析、研究、信息收集、素材整理、事实核对、
   交叉比对、来源确认，一个都不能少。
2. **深入分析类**：研究业界论述、讨论、观点、判断、论文、新闻、研究报告，
   多方信息综合后，再做系统性全局性的文章架构和内容撰写。
3. **完成后核实**：成稿后做深度核实和交叉比对，确保素材、信息、案例、
   图片、图表、三方资源尽量丰富准确。

## 八、表述偏好：客观无偏见

1. **无偏见歧视**：不带偏见和歧视；涉及国内厂商不贬低、不站队攻击、不传谣。事实清楚时可以用有冲击力的说法，偏正面不等于回避事实（`core-voice.md` V21）。
2. **敏感言论**：涉及敏感言论如无法确定，先和用户讨论再定稿。
3. **信息汇总类**：尽量用客观官方、三方原图、图片、数据表、图表阐述观点，
   文字作为补充，简单精炼。
