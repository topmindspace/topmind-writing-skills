# 平台规格 · 公众号 vs X

同一件事，写两版。内容一致，篇幅和格式按平台调整。

## X 版

- 长度：一条纯文本帖，约 1000 字以内都可以，没有 280 字限制；首行一句简单的话题陈述（core-voice V05）。更长、需要多节多图的内容写成长文（X Article，走 `topmind-x-article`）。
- 语言：默认中文。英文是例外：只有受众明确是英文区、或素材本身就是英文速报时才用英文（沿用数据榜单型的英文起手）；中文写作沿用榜单速报型的结构。
- 图片：1–4 张，首图最重要（时间线上只显示首图）。
- 格式：纯文本 + 图片。不用 Markdown 标题、加粗和列表（X 不渲染）。
- **列表与交付**：分点默认「·」，行多用「1）」，短列表才用 emoji，较长短文用【小标题】（禁用 `- ` `1. `）；正文是一段可复制纯文本，链接（含来源）、原图另发——见 [x-delivery-contract.md](x-delivery-contract.md)（必读）与 [x-post-format.md](x-post-format.md)。公众号版才用 Markdown 列表，内容与 X 版一致。
- 结尾：事实讲完就停，不硬加收尾句（core-voice V10）；空一行，最后一行写话题标签。正文不放来源链接。
- **话题标签（hashtag）**：默认 2 个（宽泛词 + 主题词，core-voice V27），最多 3 个，属于正文末行；备选标签写在说明里。
  - 取法：一个宽泛词（如 `#AI`）+ 一个主题词：榜单 / 基准 / 发布类用榜单名或产品通用名；论文类用主题词；机制类用技术名词。
  - 位置：放在最后一行，不夹在正文或列表中间。
  - 中英文：中文帖用中文话题，英文帖用英文驼峰（如 `#PromptCaching`），不加空格和标点。
  - 不堆砌：不叠同义词，不蹭无关热点；不用诱导互动、刷量或敏感话题的标签；传闻类不用会让人以为已证实的标签。
  - 公众号稿不加话题标签。
- 交付：X 正文一条消息或一个 `text` 块（不出 HTML），链接一条、图片一条另发；emoji 可选：标题行首 0–1 个与关键词对应的 emoji，人设点缀最多 2 个、只放首尾（见 [emoji-system.md](emoji-system.md)）。
  用户明确要一键复制 HTML 时才跑 `scripts/md2x-html.py`（`--images-from 公众号短文.md`，禁止手工拼 `--images`）。
  交付前跑 `python3 scripts/lint_x_post.py X短文.txt`，E 类清零（含 E10 URL、E11 来源行、E12 配图说明），W 警告每条有结论，H 提示只供判断。
- 骨架：

  ```text
  首行：是什么 + 最关键的事实

  xx：
  · 数据 1（行多用「1）」）
  · 数据 2

  #话题1 #话题2
  ```

## 公众号版

- 长度：约 300–800 字（与 SKILL.md 同一口径）。比 X 版多 1–2 句背景（"这是什么榜单""为什么重要"）。
- 标题：15 字内，带数字或结论。"[模型] 登顶 [榜单]：[分数]"。
- 图片：1–4 张，原图优先，Markdown 里用 `![图注](图片路径)` 引用。
- 格式：标题 + 导语（一句） + 列表 + 图 + 来源。
- 不写"前言导读""小结"这种长文结构——短文不需要。
- 交付：Markdown 正文（不出 HTML）。用户明确要公众号排版 HTML 时才跑 `scripts/md2wechat.py --embed-images --no-toc`，完整排版包转 `topmind-wechat-post`。
- 示例结构：
  ```markdown
  # [标题]

  > [导语一句]

  [结论段，2–3 句]

  - 数据 1
  - 数据 2
  - 数据 3

  ![图注](图)

  来源：[链接]
  ```

## 对照表

| | X 版 | 公众号版 |
|---|---|---|
| 长度 | 一条，约 1000 字内 | 约 300–800 字 |
| 标题 | 无（首句即标题） | 15 字内 |
| 背景 | 不写 | 1–2 句 |
| 图片 | 原图 1–2 张，无原图先问 | 原图 1–4 张 |
| 交付 | 正文一段纯文本，链接、原图另发 | 单独一个 markdown 块（HTML 仅按需） |
| 来源 | 另发，不进正文 | 文末来源行 / 文内链接 |
| 列表 | 默认「·」，行多用「1）」，短列表才用 emoji | Markdown 列表 |
| 话题标签 | 默认 2 个，末行 | 不加 |
| 语气 | 更短更冲 | 稍完整 |

## 开头怎么起

开头一句就交底：读者 3 秒内看到那个数字或结论（第 0 层原则 2）。

| 选题 | 开头写法 |
|---|---|
| 数据榜单 | 先一句判断，再给最扎眼的数字 |
| 榜单速报 | 模型 + 名次 + 榜单 + 分数，一句说完 |
| 论文解读 | 先一句判断，再一句讲新思路 |
| 机制讲解 | 先一句痛点，再按步骤讲 |

## 发前自检三问

1. 删掉一半字，结论还在吗？在就删。
2. 每个数字都能在另发的链接里找到一手出处吗？找不到就删或补来源。
3. 不看图，文字成立吗？不看文字，图有信息吗？都成立，图和文才各司其职。
