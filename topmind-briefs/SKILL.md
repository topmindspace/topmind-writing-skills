# topmind-briefs · 高信噪比干货短文与快讯改写

把一件事讲清楚、讲得有人味，让读者刷到第一眼就知道**跟自己有什么关系、能拿走什么用**。默认中文；当前用户的语言、篇幅、风格和平台要求优先。

## 一、按稿型选开口与结构策略（不套单一模板）

不同题材靠完全不同的支点立住。动笔前先判断这篇短文属于哪一类：

| 稿型方向 | 开口方式（第一句） | 核心展开与收尾边界 |
|---|---|---|
| **1. 经验技巧 / 提示词干货** | **结果或反差数字直接做第一句**（保留钩子，如「加一句提示词，主动重构率从 10% 涨到 50%？」） | 放上可直接复制的原件（英文提示词/命令 + 一句中文大意）→ 适用场景 → **画清「什么时候别用」的负面边界**（收藏驱动） |
| **2. 新品 / 硬件 / 模型发版** | **日常体感换算或切身痛点先行**（如「41 克」译为「跟普通眼镜差不多重」；语音升级译为「报手机号中途停顿不再被机器人插嘴打断」） | 砍掉购买地区/年龄/机型门槛、到货日与高管全称（首席执行官写 CEO）；结尾可带锚定价格问一个具体真问题（「395 美元你会买吗？」） |
| **3. 安全事件 / 突发传闻** | **接住第一反应的真疑问**（如「某平台被黑了！！？」） | **紧接一句澄清真实影响范围**（如「是第三方插件被入侵，不是主站源码被黑」），再用紧凑 `1）2）` 列官方回应与操作建议 |
| **4. 平台更新 / 榜单 / 论文** | **带态度的定性先行**，或最反常的跑分/成本对比先行 | 先给一句内行定性，再列 `1）2）` 变化；论文与榜单把结果和测试口径/局限一起交付 |
| **5. 规则变化 / 社区观察** | 先给通俗定位（如「一升一降」）或明确观察结论 | 区分「开源代码参数变动」与「线上实际生效」；保留作者主观温度（「仔细聊了一轮，我倒觉得……」），不代编亲历、不凭空补申诉方法或结果保证 |

需要完整改稿案例与跨体裁经验时，按 [knowledge-library.md](references/knowledge-library.md) 检索 `brief-value-first`、`brief-news-to-post`、`voice-peer-stance`、`de-ai-mechanisms` 等卡片；也可随时用 `scripts/knowledge.py add` 扩展新策略。更多样张见 [creative-practice.md](references/creative-practice.md) 与 [examples.md](references/examples.md)。

## 二、写作与去 AI 味核心心法

1. **跟朋友说话，不是交新闻通报作业**：
   - 查证是作者的底子，但「谁先爆料、两家媒体口径差几分钟、暂未回应、尚未确认」等**查证作业过程放在代码块外说明**，不塞进短帖正文。
   - 影响读者判断可信度的关键归因用自然人话留在正文（「据某媒体报道」「厂商自测」「网上有人反映」）。
2. **邻座身位与具体点名**：
   - 像坐在读者旁边的同行朋友。把居高临下的讲师命令（「别无脑开最高档」「不要再白白浪费」）改成邻座商量（「都开最高档吗？可能大多数时候次高档就够了...」）。
   - 把受众叫具体（「20 美元档的兄弟」「做评测、跑榜单的兄弟们注意了」）。
3. **严守「我」的边界，保留个人口吻**：
   - 作者未提供亲历时，严禁代编「我看到」「刚打开试了下」，用「有人实测」「官方文档说」代替。
   - 当作者原稿带有鲜明主观判断时，只减弱缺乏实证的绝对因果，**绝不把作者原本有温度的口吻洗成冷冰冰的官方综述**。
4. **七分留白与删尾测试**：
   - 写完把最后半句或最后一段删掉读一遍——砍掉「原来模型也一样，自己家的房子才舍得装修」这类强行升华的漂亮比喻，停在事实、适用边界或真问题上。更多见 [core-voice.md](references/core-voice.md) 与 [de-ai-rules.md](references/de-ai-rules.md)。

## 三、平台排版与图文交付

- **X 普通短帖默认习惯**：
  - 按**语义段落空行**（不搞每句空一行）；有并列要点时优先用紧凑 `1）2）`（无并列内容不硬凑列表）。
  - 默认正文不放 URL 与 `#` 话题标签（正文写工具名/命令，链接放块外另附）；若场景确实需要随文附入口链接则灵活保留。
- **公众号短文（约 300–800 字）**：支持小标题、代码块、安装命令与随文参考链接。
- **高信噪比配图**：
  - 纯文字成立就直接交文字。需要配图时，力求**一张图讲清主要变化、事实边界与作者建议**，并将「客观证据（代码/原文）」与「作者建议」在视觉上分区。
  - 论文/文档截图高亮关键句并保留上下两行真实上下文，**绝不自己排版伪造假论文页或假官方截图**；生成或概念图涉及界面时标明 `功能示意，不是实拍`。详见 [image-sourcing.md](references/image-sourcing.md) 与 [platform-cover-specs.md](references/platform-cover-specs.md)。
- **文件与渲染**：默认每条一个可复制纯文本块，说明放块外（见 [x-delivery-contract.md](references/x-delivery-contract.md)）。需落盘或转公众号 HTML 时见 [platform-specs.md](references/platform-specs.md)。只负责起草，不擅自执行外发。

## 四、按需辅助检查（非硬门禁）

```bash
python3 scripts/lint_x_post.py X短文.txt --kind news
python3 scripts/de_ai_lint.py 公众号短文.md
python3 scripts/format_text.py X短文.txt --mode short --out 排版稿.txt
```

检查器仅帮助发现未闭合围栏、粗体残留等格式破损，并提供语境线索；`W/H/I` 提示不要求清零，**不作为阻断交付的门禁**。改稿复盘见 [revision-workflow.md](references/revision-workflow.md)，复杂查证见 [research-mode.md](references/research-mode.md)。
