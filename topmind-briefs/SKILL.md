# topmind-briefs · 干货短文（X + 公众号）

一件事，一段话，讲完就停。短文不是长文：**默认不出 HTML、不做排版包**，交付的是可以直接复制粘贴的文字。

> **必读（交付格式是硬约束）**：[references/x-delivery-contract.md](references/x-delivery-contract.md)——X 正文是一段可直接复制的纯文本，**不含 URL 和来源行**；链接一条、图片一条另发。分点默认「·」，行多用「1）」，短列表才用 emoji，禁用 `- ` `1. `；emoji 不强制。
> **写法规则**：[references/core-voice.md](references/core-voice.md) 的短文条目（V01 V05 V08–V13 V16 V20–V22 V24–V28 V32 V34 V35 V38–V40）；去 AI 味按 [references/de-ai-rules.md](references/de-ai-rules.md)（短帖看第五节 S01–S10）。

- 跟 `topmind-viral-posts` 的区别：那是段子（一句一行、钩子、反转）；这是**信息型短文**（快讯、新品、羊毛、榜单、论文、实测、观点一句话），一条讲清一件事。
- 跟 `topmind-x-article` / `topmind-wechat-post` 的区别：那两个是长文（数千字、多节多图、HTML 发布包）；本技能 X 版是一条纯文本短文（约 1000 字内），公众号版 300–800 字。
- 现成文字只要排版 → `topmind-format`。

## 先读：写作原则与信息设计

本技能建立在两份共享文件上，动笔前先读：

- [references/social-writing-principles.md](references/social-writing-principles.md)：8 条社交媒体写作原则（先想清楚、结论先行、每句都有新信息、形式跟内容走、简单清楚、原图优先、站在读者那边、真实有分寸）
- [references/information-design.md](references/information-design.md)：内容 → 形式决策表、篇幅和密度、去啰嗦的判断法
- 措辞和口吻在这两层之上，见 [references/core-voice.md](references/core-voice.md)

短文：首行给最狠的事实；3 个以上要点用「·」分行；原图另发，正文不复述图。

## 内容类型（九种）

先判断这条是哪一类，再动笔。各类的首行、结构、收尾不一样：

| 类型 | 适用 | 首行 | 结构 | 收尾 |
|---|---|---|---|---|
| 快讯（首发） | 官宣、上线，刚发生 | 是什么 + 最狠的一个数；比的对象选读者认识的知名对手，不跟上一版比 | 一两行事实 + 一张原图就够；跑分放图里，不逐条复述 | 「...」或不收 |
| 快讯（晚到） | 首发窗口已过 | 换新角度：实测、算账、求证、把别人的争议接住 | 第一手数字或一个新事实 | 「...」 |
| 预告 / 传闻 | 预告、文档里出现、灰度 | 动词照口径写：「要来了？！」「文档里已经改名了」 | 线索 + 官方还没给的东西，直说「还没公布」 | 「？！」 |
| 新品 / 工具推荐 | 好用的新东西 | 真疑问（「难道没人用…吗？」）或一句真心推荐 | 两三个对读者有用的点（免费、手机能用、不用折腾） | 「...」 |
| 羊毛 / 优惠 | 限时、免费、大促 | 一句话说能马上拿到什么 | 一句 + 一张图；截止时间写清 | 不收 |
| 榜单 / 数据 | 排名变化、基准评测 | 谁第一、领先多少 | 「1）」列前三 + 一张榜单原图 | 不收 |
| 论文 | 新方法、新结论 | 一句结论 | 一句方法 + 3 条「·」要点 + 论文原图 | 不收 |
| 实测 | 自己跑过 | 结果一句（翻车、快、贵） | 任务、数字、截图；数字必须是作者真跑出来的 | 自嘲，或一个真问题 |
| 观点 / 经验一句话 | 立人设，原来段子里的干货类 | 一句内行的轻判断 | 两三行依据，像老司机吐槽，不像讲台上讲课 | 判断本身 |

几条共同规则：

- **一眼快餐**（X 版）：只留上线事实、关键数字、亮点。查证过程和口径说明（官方称、按图估读、据我查）放进交付说明的「口径提醒」，不进正文；公众号版照常写口径（core-voice V39）。
- **口径照实**：预告不写成发布，灰度不写成官宣，文档里出现不写成上线；标题动词跟着口径走（V40）。
- **一个事件多角度连发**：每条一个主角、一个角度（性能一条、价格一条、八卦一条），不在一条里全塞。
- **外链放首条评论**：正文自足，链接另发。
- **配图**：图本身就是信息时才配（跑分、截图、价格卡、榜单）；观点和实测吐槽可以纯文字。

## 时效

- **首发窗口以分钟计**：官宣后尽快发；同样的内容，晚一两个小时就只剩平铺播报，表现最差。
- **晚了就换角度**：实测、算账、求证、站队，不再重复别人已经发过的那句。
- **预告和正式发布分开写**：预告当天写「要来了？！」，正式发布时再写一条快讯，两条各自成立。
- **平铺播报是最弱的写法**：同一件事，带一句真实反应、一个站队或一个真疑问，都比「XX 发布了 + 参数」好。

## 何时不用

- 把现成文字格式化、转段子、加空行和 emoji → `topmind-format`
- X 长文（数千字深度稿）、发 X 文章 → `topmind-x-article`
- 公众号长文、公众号排版 HTML → `topmind-wechat-post`
- 引流互动型短帖（第一人称、段子、钩子、涨粉、互关）→ `topmind-viral-posts`
- 单独出长图、海报、信息图 PNG → `topmind-poster`；只要封面、头图 → `topmind-cover`
- 单独改一篇现成稿子、去 AI 味、质检 → `topmind-revise`
- 把稿子发到 X → `topmind-x`（发帖连接器，须用户确认后才发）

## 语言：默认中文

- **默认中文**：标题、正文、配图说明一律用中文，不需要用户每次声明。
- **英文是例外**：只有用户**明确说**「写英文」时才用英文。消息里夹英文词、给英文素材、引用英文原文，都不算要求写英文。
- 官方产品名、论文标题保留英文；引语正文写「人名：中文意思」，英文原文记进素材来源，不在正文里原文加括注（core-voice V13）。

## 尊重原始信息（硬约束：事实）

1. **原始信息**：事实、数字、时间以一手来源为准（官方公告、更新日志、论文、原帖、财报）；二手报道至少找 2 个独立来源交叉确认，无法核实的承重事实删掉。
2. **原文**：引用原话时逐字照录并加「」，写明出处；不把转述写成引语，不改原文数字的单位和口径。
3. **原图**：配图用官方截图 > 官方基准图 > 第三方榜单实拍 > 论文原图，保留原图不裁掉关键信息，不用 AI 图冒充原图。
4. **口径**：分清厂商口径、传言和已证实的事实。X 版正文不写「官方称」「厂商口径」，口径写进交付说明的「口径提醒」；公众号版照常标注。有一手信源但还没完全确认的热点，直陈并在首行或末行用一次「？！」，不写泛泛的「据报道」，纯传闻不写（core-voice V22、V39、V40）；自己的判断写成「预计」「大概率」「现在看起来…」，与事实分开写。
5. **不洗稿**：观点可以撞，表达必须原创；不照搬聚合站或别人帖子的行文。

## 工作流

顺序固定：**信源 → 原帖原图 → 内容 → 排版**，前一步没做完不进下一步（见交付规约第一节）。

1. **定位**：这条是九种内容类型里的哪一类？想让哪种人来评论（来补充的懂行读者、来抢羊毛的、来站队的）？首发还是晚到？
2. **核实信源**：一篇只讲一件事。先找一手来源（官方公告、更新日志、论文、仓库、当事人原帖）；分清厂商口径、传言和事实。记下每条的**来源名称、发布时间（时区）、URL**——这些另发给用户，不进正文。
3. **找原帖、原图**（写字之前，按 [references/image-sourcing.md](references/image-sourcing.md)）：原帖链接、官方图 / 截图 1–2 张，来源记进交付说明；自制图只作兜底，标「自制」和数据来源。
4. **写内容**：
   - 先想清楚这条要传达的一件事（第 0 层原则 1）；并列要点、对比、步骤按 [references/information-design.md](references/information-design.md) 的决策表定成「·」分行、分行对照或「1）」，不写成一段话；
   - 首行按类型写（见上表）：快讯「是什么 + 最狠一个数」约 30 字内；观点、实测、真疑问的首行可以长一点。只看首行也拿到信息；不用设问钩子，真里程碑把「第一」放句首（core-voice V05、V20）；
   - 口吻像还在学习的普通人：讲自己看到、试过的，不站讲台，不确定就直说（core-voice 原则 9）；
   - 具体数字和场景，说人话，事实讲完就停；不用「你会换吗？」这类套路互动问句，作者真拿不准的问题可以问（V10、V34）；对比给出对象和定语，不写「约 / 左右」，不用千分位（V12）；
   - 读者不关心的背景删掉，借来的热点一句带过；推测写成问句（V22）；精炼不砍双音词，不夹没必要的英文小词（V38）；
   - **一眼快餐**：正文不写查证过程和口径说明（V39）；
   - **成稿后去 AI 味自查**：按 [references/de-ai-rules.md](references/de-ai-rules.md) 过一遍（第五节 S01–S10 专看短帖），再做一次删尾测试：删掉最后半句更好就删。
5. **排版**（目标：方便阅读），按 [references/platform-specs.md](references/platform-specs.md)、[references/x-post-format.md](references/x-post-format.md)、[references/x-layout-patterns.md](references/x-layout-patterns.md)：
   - 一段 1–3 行，段间空一行；3–7 条并列信息才用列表，前一行写「xx：」引导语，2 条就写成两句；
   - 分点默认「·」，行多或有顺序用「1）」，短列表（3–4 条）才用 emoji（🔹 / 1️⃣ / ✅❌），较长短文用【小标题】分节；禁用 `- ` `* ` `1. `（V25）；
   - emoji **不强制**；要用就只用 TopMind 体系（[references/emoji-system.md](references/emoji-system.md)）；
   - 中英混排：英文专名保留原文，中英之间加半角空格；
   - 话题标签默认不带；要带最多 2 个（宽泛词 + 主题词，V27）；不用 Markdown（X 不渲染）。
6. **写公众号版**（用户要双平台时）：300–800 字 Markdown，事实与 X 版一致，可以多写口径和背景；不写前言导读。「·」列表每行一条，渲染脚本会逐行分开。
7. **配图**：图本身就是信息时配，交付 1–2 张（官方图、原帖配图 / 截图、基准图、榜单实拍），每张写一句图注说明它证明什么；给可直接打开的图片地址，能下载就下载到交付目录。**该配图却没有可用原图时，主动问用户「要不要配图？可以用 topmind-cover 出一张 16:9 封面」**，用户说要再调用 `topmind-cover` 的「X 短文封面」（16:9，1200×675）；不擅自生图。
8. **自检**：
   - 每个数字都能在另发的链接里找到出处；图和文字说的是同一件事；推测已标注；
   - `python3 scripts/lint_x_post.py X短文.txt --kind news`（快讯；其他类型不加 `--kind`）：E 错误清零；W 警告每条要有结论；H 提示只供判断；公众号版跑 `python3 scripts/de_ai_lint.py 公众号短文.md`，文件夹结构跑 `python3 scripts/check_article.py <短文文件夹>/`（短文不要求文件名 = 标题、不要求封面）；
   - 需要统一排版时可跑 `python3 scripts/format_text.py X短文.txt --mode short --out X短文.txt`（只动排版不改字）；几个开头可选时加 `--variants 开头备选.txt`，拼成几条完整成品；
   - 用户要求改稿时，转 `topmind-revise`（`mode=revise genre=short`）；没装时按 [references/revision-workflow.md](references/revision-workflow.md) 手动走。
9. **交付**（只交付，不发布）：见下节「交付格式」；落盘时 `X短文.txt` 只放正文，链接 / 图片 / 口径提醒写进 `交付说明.md`。

## 交付格式

默认交付纯文本，不生成 HTML，严格按 [references/x-delivery-contract.md](references/x-delivery-contract.md)（含正反例）：

1. **正文**（一条消息或一个独立 `text` 块）：一段可直接复制的纯文本——标题行、正文、列表（可选的末行话题标签）；**不含 URL、来源行、配图说明、口径说明**。thread 每条一块；几个开头可选时拼成几条完整成品，每条一块。
2. **链接**（单独一条）：`来源名称｜发布时间（注明时区）｜URL`，每条承重事实一行，原帖链接也放这里；发布时间取原文页面，没有就写「未标注」。
3. **图片**（单独一条）：1–2 张，`[图1] 图片地址或文件名 — 图注；来源`；视频给封面帧地址并注明。没有原图写「未找到原图」，并问：「要不要配图？可以用 topmind-cover 出一张 16:9 封面。」
4. **公众号版**（用户要时）：单独一个 `markdown` 块，可以有文内链接。
5. **口径提醒 / 说明**：哪些是厂商口径、哪些还没证实、改了什么，放最后（给作者看，不进正文）。

**HTML 只在用户明确要求时出**（例如「出个一键复制 HTML」「公众号要排版好的版本」）：
`python3 scripts/md2x-html.py X短文.md --out X短文.html --images-from 公众号短文.md`、
`python3 scripts/md2wechat.py --input 公众号短文.md --out-dir <交付目录> --slug <短名> --embed-images --no-toc`。
两个脚本的唯一真源在仓库 `shared/scripts/`，本目录是逐字节副本；`[图N]` 顺序由脚本校验，禁止手工拼 `--images`。
需要完整公众号排版包时转 `topmind-wechat-post`。

## X 版示例

快讯（首发，虚构）：

```text
某模型低调上线新版：编程评测 31 → 42，价格不变

网页、App、接口已全量切换，权重开源。

几项关键提升：

1）编程评测：31 → 42
2）推理评测：37 → 43
3）智能体评测：74 → 77，比某知名闭源模型高 3 分

单任务成本两毛钱出头...
```

链接（另发）：`官方发布帖｜2026-10-17 16:00（UTC+8）｜https://example.com/release`
图片（另发）：`[图1] 官方评测表 — 各项分数；来源：官方发布帖`
口径提醒（另发）：分数是厂商自测，独立榜单还没出分。

羊毛（虚构）：

```text
今晚 8 点某云的 GPU 实例一折，限前 500 台
```

预告（虚构）：

```text
某模型新版要来了？！

官方说下周发，上下文翻倍，价格还没公布...
```

（示例中的名称与数字为虚构演示。更多示例见 [references/examples.md](references/examples.md)。）

## 话题标签

X 版默认不带话题标签。要带最多 2 个（属正文，是正文最后一行）：一个宽泛词（如 #AI）+ 一个主题词（榜单名、产品通用名或领域词）；不蹭无关热点，不用诱导互动或敏感标签。公众号稿不加话题标签。细则见 `references/platform-specs.md`。

## 和其他技能怎么配合

| 场景 | 组合 |
|---|---|
| 写完再统一排版 | 本技能 → `topmind-format` 短文体（只排版不改字） |
| 用户要改稿、过一遍质检 | 本技能 → `topmind-revise`（`mode=revise genre=short`） |
| 没有原图、用户同意配图 | 本技能 → `topmind-cover`「X 短文封面」 |
| 内容太多、写成长文 | 转 `topmind-x-article`（X 长文）或 `topmind-wechat-post`（公众号长文） |
| 要一张数据长图 | 本技能出文案 → `topmind-poster` 出图 |
| 同一事件出段子 | 本技能出干货版，`topmind-viral-posts` 出引流版，事实与来源保持一致 |

## 运营约定

- 只起草，不代发。发布前用户确认。
- 数字必须有一手来源（链接另发）；厂商口径写进口径提醒（公众号版在正文标注）。
- 不碰医疗建议、投资建议、政治站队。
