# topmind-briefs · 干货短文

把一件事讲清楚，交付可直接使用的 X 短文或公众号短文。默认中文；用户的语言、篇幅、风格和平台要求优先。

## 先决定读者能拿走什么

根据现有素材直接着手。新闻需要可靠信源，实测需要作者实际结果，观点可以从一个具体观察展开。单条任务给一条完成稿；角度有分歧、用户要选题或同题连发时，再探索不同方向。

| 方向 | 起笔方式 | 值得放大的东西 |
|---|---|---|
| 快讯 / 预告 | 已发生的变化，或清楚标注的计划 | 时间、范围、一个关键事实 |
| 新品 / 工具 | 读者正在解决的具体问题 | 谁用得上、代价、限制 |
| 榜单 / 论文 | 结果和测试条件一起说 | 比较口径、方法、适用范围 |
| 实测 / 算账 | 作者测到了什么 | 任务、结果、复现条件 |
| 经验 / 观点 | 观察、问题或判断 | 依据、反例、下一步 |

这些方向可以混合。时效已过的新闻，可以补实测、解释一个争议，或给读者新的使用角度。

## 参考与候选

- 看 [创作方法与样张](references/creative-practice.md)，挑一个接近当前任务的完整样张，理解它为什么成立。
- 用户给了原帖或参考作品时，实际打开阅读；提取角度、证据、节奏等可迁移经验。访问失败就说明读到了什么，继续用已确认材料。
- 风格未定时，可写事实直给、使用场景、轻判断等少量有实质差异的完整候选，再选最贴题的一条。用户明确要一条时直接交成品。
- [内容样例](references/examples.md) 和 [口吻经验](references/core-voice.md) 提供更多写法，按需读取。

## 写作与核对

先抓主事实，查资料、找图和起草可以交替进行。把事件日期、来源和必要测试条件记下来；动态信息回源核实。

正文保持读者理解所需的限定：如“厂商测试”“约”“灰度”“尚未确认”。问号或感叹号不能代替这些说明。引用照录，转述与翻译标清性质；作者没提供的经历和实测结果换成观察或待验证问题。

形式按信息选：短段、列表、分行对照、thread 都可。emoji、标签、首行长度和收尾方式取决于内容与作者习惯。公众号版可从 300–800 字起步，用户要更短或更深时随内容调整。

## 图片与交付

图能证明结果或帮助理解时，优先读原帖、官方图和论文图；自己的结构与判断也可以画成示意图，标明“自制 / 示意”及依据。纯文字已经完整时直接交稿。用户已要求配图就继续完成；只要求文字时不额外扩展生图任务。详见 [图源经验](references/image-sourcing.md)。

默认每条一个可复制的纯文本块，说明放块外。来源链接通常另列；下载、报名、证据核对等需要正文链接时可保留。必要归因留在正文，详细查证笔记另列。双平台时另给公众号 Markdown；只交付所需平台。

需要落盘时可用 `X短文.txt`、`公众号短文.md`、`交付说明.md`，沿用用户已有目录。默认文字交付；用户要 HTML 时再使用随包渲染器，见 [平台操作](references/platform-specs.md)。本技能起草，不执行发布。

## 按需检查

```bash
python3 scripts/lint_x_post.py X短文.txt --kind news
python3 scripts/de_ai_lint.py 公众号短文.md
python3 scripts/format_text.py X短文.txt --mode short --out 排版稿.txt
```

检查器提供线索，风格提示可以保留；修正实际格式破损和未处理图片占位。改稿看 [修改方法](references/revision-workflow.md)，复杂研究看 [研究方法](references/research-mode.md)。简单稿件一次通读、核对关键事实即可，无需凑报告或评分。

## 分工

互动段子用 `topmind-viral-posts`；现成文字只排版用 `topmind-format`；长文交付用 `topmind-wechat-post` / `topmind-x-article`；独立改稿用 `topmind-revise`；封面与信息图用 `topmind-cover` / `topmind-poster`。这些技能按任务需要组合，缺少时使用本包参考与脚本继续完成可做的部分。
