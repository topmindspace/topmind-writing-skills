# 封面设计判断与出字协议

设计参数是可调整的起点；JSON 字段、文件路径和实际文字正确是工具与交付约束。这里把两者分开，避免用模板阈值评判所有封面。

## 从读序决定版面

先判断第一眼看标题、人物 / 物件，还是两者的关系；再决定第二眼的落点。可以有单焦点，也可以用有序的多焦点形成阅读。网格可帮助对齐，不对称、出血和实验排版也能成立。

| 当前问题 | 可尝试的调整 | 另一条可行路径 |
|---|---|---|
| 标题没有存在感 | 改字重、尺度、位置、断行或局部对比 | 让图像承载第一眼，标题辅助 |
| 画面太满 | 合并组、拉开间距、改变裁切 | 保留密度但建立读序 |
| 太像模板 | 换媒介、意象、镜头或字图关系 | 保留版式，用文章独有细节 |
| 字图互相抢 | 调整明暗、位置和面积 | 有意形成对抗，保留清晰入口 |
| 信息切坏 | 按另一比例重排 | 独立制作该版本，不硬裁 |

## 字号、层级与网格

字号随字面、字数、画幅与实际缩略图决定，不用统一画面高度比例。重要文字要能读清；装饰字、编号与纹理不一定承担同等阅读任务。可以一大一小，也可以同字号通过位置、字重、疏密区分层次。

网格可从单轴、双栏、跨栏、中心、边缘或自由排列开始。行距与字距要看具体字体；宋体和窄黑、中文与拉丁字的字面不同，不能直接套同一数值。保留语义词组，断行可以制造节奏，但不改作者标题的意思。

颜色可单色、近似色、互补或多彩；60-30-10 是其中一种起点，不设颜色数量上限。字体数和装饰数也由关系判断，不把多个字效自动判成乱。复杂背景上的字可换位置、底板、描边、投影或局部色彩，哪种有效要看成图。

## 裁切与可读性

平台与导出预设见 [platform-cover-specs.md](platform-cover-specs.md)。没有适用于所有平台的中央横带或固定百分比安全区。根据实际横竖版、宽图和方图逐版检查；设计中的出血可以存在，关键字和主体被误切则需要修正。

自动对比度测量和边距提示是诊断线索，不是对封面美学的认证，也不把界面可访问性数字机械套给所有艺术文字。实际可读、说明性文本与使用场景仍需人工或视觉工具判断。

## 制作路径

- 整张生成：适合字与场景融为一体、材料字和实验画面；逐字核对。
- 背景 / 主体 + 后期叠字：适合长标题、精确中文和多次改字；从一开始就可采用。
- HTML / SVG / 排版工具：适合纯文字、编辑构图、精确形状和可编辑源文件。
- 原图裁切 + 排版：适合事实图、摄影与真实产品；生成补景不冒充原始证据。

## title-engine 的真实协议

`--list-fonts` 列实际可用别名；`font` 也可使用已核实的字体文件路径，工具不会自动下载字体。别名不保证本机已安装，使用前实际检查。字体许可与字库覆盖按实际文件核对，不用编码表推断字体会不会写错。

```bash
python3 scripts/title-engine.py --list-fonts
python3 scripts/title-engine.py --check spec.json
python3 scripts/title-engine.py 背景.png spec.json --out 封面.png
```

一份可编辑 spec 的示例（参数只描述此版式）：

```json
{"layers":[
  {"type":"text","role":"main","text":"读慢一点","font":"song","size":0.21,"fill":"#24221E","x":0.12,"y":0.42,"anchor":"lm","tracking":0.08},
  {"type":"text","role":"label","text":"阅读与日常","font":"hei-medium","size":0.055,"fill":"#675D50","x":0.12,"y":0.76,"anchor":"lm"}
]}
```

图层类型为 text / deco / occlude；角色 main / sub / label / ornament 用于工具诊断，不能当作作品必须有三级文字。坐标为比例小数或像素整数，size 为正的比例或像素。完整效果字段见脚本开头与 [typography-system.md](typography-system.md)；未知类型、非数值字号、空文字等结构问题仍报错。

默认 `--check` 只给设计提示；`--strict` 是作者主动采用旧模板参数时的兼容选项，不能自动为每张图启用。模板提示不表示作品不合格，用户的版式要求和实际成品优先。用 check-title 也只获取核字线索，不因长标题、繁体或生僻字改坏原文。

## 参考与判断依据

[Carbon Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview) 区分面向任务的 productive 与面向编辑表达的 expressive 字体体系，并说明字号与字重共同形成层级。本库借鉴“不同用途采用不同表达”的思路，不将 IBM 的具体字体或参数当成封面标准。

[艺术文字生成综述](https://arxiv.org/abs/2407.14774) 区分字的材质效果与语义形态两类思路。本库据此提供更多字形方向；没有据此声称任何当前模型在指定标题长度下的成功率。
