# 事实核查（质量三关第一关）

> 适用：topmind-revise 的 ① 事实；topmind-wechat-post / topmind-x-article 嵌入调用时同样执行。
> 场景规则编号见 `core-voice.md`（V12、V13、V21、V22），改写边界见 `de-ai-rules.md`。

## 一、先列承重事实

把稿子里会被读者当真、被转述的句子挑出来，逐条核：

| 类型 | 例子 | 怎么核 |
|---|---|---|
| 数字 | 星标数、下载量、价格、百分比、参数量 | 回到一手信源看当前值；写「截至 X 月 X 日」 |
| 日期与顺序 | 发布时间、谁先谁后 | 对官方公告、仓库提交记录、原帖时间 |
| 排名与「第一」 | 「第一个」「最大」「首个」 | 找得到明确出处才写；核实不了就换说法（「较早的一批」「目前公开信息里最大的」） |
| 引语 | 某人说了什么 | 逐字对原话；不加强、不换语气、不拼接 |
| 归属 | 谁做的、谁发布的、谁投资的 | 对官方页面或本人账号 |
| 否定结论 | 「没有」「不支持」「从未」 | 换一种查法再查一遍（换关键词、换语言、查更新日志） |

## 二、按信源强度写

| 信源 | 写法 |
|---|---|
| 官方公告、本人账号、仓库、论文 | 直陈 |
| 一手信源有、但还没完全确认的热点 | 短文可以直陈并在首行用一次「？！」；长文写「据 XX」 |
| 多家媒体转述、无一手信源 | 写「据 XX 报道」并点名媒体，不写泛泛的「据报道」 |
| 纯传闻、截图来源不明 | 不写 |

## 三、上一版的数字全部重核

改稿时不默认上一版是对的：数字、日期、排名全部重新对一次。动态数字（星标、下载量、榜单名次）写当时值并注明时间，必要时给一个整数口径（「6 万多」）。

## 四、未来的说法

结论推不出来就不写满：用「预计」「大概率」「可能」；能找到一条支撑事实（已公布的路线图、已开的测试）就附上。

## 五、查不到怎么办

不替作者决定。列进改稿报告的「未核实条目」，写清：原句、需要的证据、已经查过哪里。作者确认前，改稿只做不改变事实的修改。

## 六、作者自述与回忆

稿子里写「我当时……」「那天我只会……」这类作者自己的经历，同样是承重事实：

- 有记录（聊天记录、对练记录、提交历史、截图）就对记录，按记录里的说法写；
- 没有记录、只是写稿时的推测或润色，不替作者补；列进「未核实条目」，或改成记录里能找到的说法；
- 作者给的数字口径（「大概跑了 3 个小时」这类自述大概数）照作者原话保留「大概 / 约」，不要为了 V12 改成精确数，也不要自己补精确值。

## 七、素材来源文件

文章目录下的 `素材来源.md`（作者私有）是核查的第一参照：每条事实对应的链接、截图、访问时间都记在那里。改稿新增的事实，同步补进素材来源；素材来源不进公开仓库，也不贴进正文。
