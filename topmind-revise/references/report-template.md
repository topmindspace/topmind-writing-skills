# 改稿报告（按任务规模取用）

简单润色交完成稿与重要说明即可；用户要审计、长文深改或多源事实核查时再使用完整报告。脚本生成的是未填写的线索骨架，检查框只在实际核过后勾选。

```markdown
# 改稿报告

目标与范围：
原稿与恢复方式：（实际文件或版本，不猜路径）

## 主要改动
| 位置 | 修改目的 | 改前 | 改后 |
|---|---|---|---|
| | | | |

## 事实与保真
实际核对过的关键数字、引用、状态和归因；有事实修正时附依据。

## 未核实项
| 原句 | 缺什么证据 | 当前处理 |
|---|---|---|
| | | |

## 重要取舍（按需）
结构、作者声音、读者理解之间如何选择。合理风格无需逐条对应 lint 编号。

## 验证范围
跑过哪些工具、实际看过哪些产物；自动提示不等于已核查。
```

`python3 scripts/revise_check.py 改前.md 改后.md --report 改稿报告.md` 可生成逐段 diff、数字与引用变化、提示列表。全面重写时没有 W 命中的段落也可能应改；超过 30% 的提示是旧经验线，不是失真证明。需要时用 `--declare 改稿报告.md` 登记“⓪ 结构”“① 事实”“② 逻辑”“作者意见”等依据。

报告与私人稿件按作者授权保存。词数可反映改动规模，但不是越短越好；嵌入写作自查可简短交付，不强制生成全套报告。
