# revision-workflow.md · 改稿流程（改稿 · 去 AI 味 · 质量三关 · 保真审计）

> **执行者**：装了 `topmind-revise` 时，改稿、质检由它执行（长文技能写完默认调用它的嵌入模式）；没装时，briefs、viral-posts、x-article、wechat-post 按本文件手动走一遍，效果一致。
> 规则来源：`core-voice.md`（场景规则 V01–V33）、`de-ai-rules.md`（结构模式与改写边界）。
> 每一轮都**先备份、记字数**，改完再记一次字数，交付时报「改前 → 改后」。

## 每轮开始

1. **声明**：「技能 · 模式（只审 / 改稿 / 嵌入 / 快审）· 文体（长文 / 短文 / 段子 / 回复 / 标题）」。
2. **备份**：把要改的稿子和配图复制到新的带时间戳目录（如 `backup-YYYYMMDD-HHMMSS-<稿名>/`），不覆盖旧备份。
3. **记改前字数**：`python3 scripts/count_words.py 稿子.md`（去掉 frontmatter、标题行、图片行、空白和 Markdown 符号）。

## 步骤（顺序不换）

| 步 | 做什么 | 完成标准 |
|---|---|---|
| ① 事实 | 承重事实（数字、排名、日期、引语、「第一」）逐条对私有素材来源，上一版里的数字一律重核；有一手信源但未完全确认的热点，短文可直陈加「？！」；纯传闻不写；「第一」核实不了就换说法；引语逐字照录，语气不升级；否定结论换一种查法再查一遍（V13、V22） | 每条承重事实能在素材来源里找到出处；查不到的列进「未核实条目」交给作者 |
| ② 逻辑 | 结论是否靠前；长文结构「过去一句 + 图、现在汇总加分析、未来判断 + 一条支撑事实」；定性准不准；对比有对象、有定语；同一事实全文同值、同一事物一个叫法 | 结构和定性说得出理由 |
| ③ 删冗余 | 删不言自明的引导语、复述图的句子、小节过渡句、无效信息（「暂未回应」「截图为证」）、段段小结。直白但啰嗦的句子只删多余部分，**不整句推倒** | 删掉的每一处都说得出理由 |
| ④ 去 AI 味 | 按 `de-ai-rules.md` 走：强信号见一次就改，弱信号叠在一起才改，语境词按 `core-voice.md` 判断；守改写边界 | `de_ai_lint.py`（短文用 `lint_x_post.py`）的 W 每条有结论；H 只供判断 |
| ⑤ 核心经验对照 | 按文体抽查 `core-voice.md` 速查表里的条目 | — |
| ⑥ 排版 | 长文 Markdown：图紧跟它证明的文字，一段 2–3 句；短文纯文本；段子一句一行；回复一行 | X 稿 E 级错误为 0 |
| ⑦ 保真审计 | `python3 scripts/revise_check.py 改前 改后`：数字、日期、引语、英文专名、确定性词有没有被改；有源稿时加跑 `audit-provenance.py`（段落级）或数字级回源 | 数字、引语的每处变化都有依据 |
| ⑧ 过度改稿检查 | 同上脚本：没有任何 W 命中却被改写的段落占比超过 30% 时提示 | 逐段确认或恢复原文 |

## 防过度改稿

1. 每处改动对应一条规则编号或一句作者意见；说不出来就恢复原文。
2. 没有命中的段落原样保留。
3. 作者改过的说法就是标准答案，下次同类位置直接用。
4. 不追求字数一定变短：变短是删冗余的结果，不是目标。
5. 不动：引语原文、专名、术语、讨论某个词本身的句子、作者故意的口语和括号里的自我纠正。
6. 有作者样本时，句长、用词、标点习惯跟样本走。

## 每轮结束

- 记改后字数，交付时写「字数：改前 N → 改后 M」。
- `revise_check.py 改前 改后 --report 改稿报告.md` 生成报告骨架，补全改动表：位置、规则编号、原文 → 改后；保留未改的命中和理由；未核实条目。改稿报告是私有文件，放在作者的工作区，不进本仓库。
- 需要派生稿（X 长文 HTML、公众号 HTML）时重新生成，再跑一遍检查与图序核对。
- **嵌入模式**（被别的技能调用）：只把终稿和三行摘要（字数前后、未核实条数、保留的提示）交回调用方，完整报告落盘。
