# 改稿实践：按目标选择动作

单独改稿可用 `topmind-revise`，未安装时按本页继续即可。短文本一次通读与核对就能完成，长文全面整改可分轮进行；不要求每次完整执行固定十步。

## 从目标到动作

| 目标 | 可用动作 | 看什么结果 |
|---|---|---|
| 信息不清楚 | 补前提、换顺序、给例子 | 读者能跟上推理 |
| 太长 | 删重复、压背景、合并、换形式 | 核心内容完整，节奏更合适 |
| 太平 | 换入口、加真实细节、尝试不同叙事 | 作者声音更鲜明，事实不变 |
| 结构不对 | 重排、拆合、改主线 | 符合用户已授权的改稿深度 |
| 只要排版 | 换行、留白、符号呈现 | 原文语义与措辞保留 |
| 事实与论证 | 回源、保留限定、补反例 | 不把推测写成定论 |

## 实际修改

文件实质修改前保留可恢复版本：已有版本控制、用户备份或新时间戳副本均可。聊天中的简短文本直接给修改结果。材料与配图没有改动时无需每轮复制整套目录。

先理解整篇，再按实际问题选结构、事实、逻辑或文字动作，允许反复交替。全面重写已获授权时无需因重排章节再询问；只要求局部修改时保持范围。

有效段落可以原样留；没有 lint 命中也可以因逻辑、节奏或作者目标而改。理由说清即可，无需对应编号。引用照录、专名准确、确定性与作者态度保真；事实确有错误时依据来源修正并说明。

## 工具辅助

```bash
python3 scripts/de_ai_lint.py 稿子.md
python3 scripts/revise_check.py 改前.md 改后.md --report 改稿报告.md
```

保真脚本的消失 / 新增和改动比例都是线索，不能自行证明失真或过度改稿。结构重组可在 `--declare` 报告里说明。段落溯源适合同构稿，不适合大幅重写、多源综述；这时改用主张、数字、引用逐项核对。

[de-ai-rules.md](de-ai-rules.md) 的 W/H/I 提示可以按上下文保留，不要求清零或逐条申辩；词面分数不能决定定稿。[core-voice.md](core-voice.md) 和 [creative-practice.md](creative-practice.md) 给替代写法。

## 交付与复盘

交完成稿、重要改动和未核实项。完整报告用于用户要求、长文深改或高成本审计；简单润色给一句理由即可。嵌入写作流程的自查按同样标准核对事实，不强制另起报告项目。

用户要求比较时可匿名展示同事实、相近预算的候选，请作者选实际愿意用的版本。不把自评提升或更少警告写成真实质量提升。需要长期沉淀时按用户要求记录场景、原因与例外。
