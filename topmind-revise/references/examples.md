# 改前 / 改后示例（虚构）

> 示例全部虚构，用来说明规则怎么落地；规则编号见 `core-voice.md`（V）和 `de-ai-rules.md`（Z / P）。

## 一、长文段落：删自明引导语和复述图片

改前：

```text
值得注意的是，这次更新带来了不少变化。从下图可以看出，新版启动时间从 3.2 秒降到了 1.4 秒，整体表现有了明显提升。
```

改后：

```text
新版启动时间从 3.2 秒降到 1.4 秒。
```

依据：Z17（「值得注意的是」假强调）、Z34 / V15（不写「从下图可以看出」，正文不复述图）、Z18（「明显提升」空泛形容，数字已经说明了）。

## 二、短文：首行和收尾

改前：

```text
重磅！某编辑器 3.0 发布，AI 编程迎来新纪元！

更新内容：
🔹 补全更快
🔹 支持本地模型
🔹 插件市场改版

这不仅是一次更新，更是开发方式的变革。
```

改后：

```text
某编辑器 3.0 发布，可以接本地模型了

更新内容：
· 补全更快
· 支持本地模型
· 插件市场改版
```

依据：V20（后续迭代不用「重磅」）、V10（事实讲完就停，删收尾句）、Z02（「不仅…更是…」）、V25（列表默认「·」）。

## 三、该保留的不要改

```text
真正的难点不在模型，在数据清洗。
```

「真正的」在这里区分了两个难点，de_ai_lint 只给 H1 提示，保留不改。

```text
他原话是「这个功能我们不会做」。
```

引语原文，不改语气、不改字。

## 四、回复

改前：

```text
非常认同您的观点！这确实是一个值得深思的问题，期待后续更多讨论～
```

改后：

```text
同意，关键是数据能不能带走
```

依据：V29（回复一行说清一个点，不客套）、Z15（客服腔）。
