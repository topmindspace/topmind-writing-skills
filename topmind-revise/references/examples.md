# 修改深度与保留：原创教学例

以下均为虚构材料，改法由用户目标决定。词表、规则编号、删字比例和“像不像 AI”不能代替读者效果判断。

## 一、精简与解释都可能更好

原稿：
```text
值得注意的是，这次更新带来了不少变化。新版启动时间从 3.2 秒降到了 1.4 秒，整体表现有了明显提升。
```

信息直给：
```text
新版启动时间从 3.2 秒降到 1.4 秒。
```

需要解释使用影响时：
```text
新版启动时间从 3.2 秒降到 1.4 秒。频繁打开应用时，这段等待会更容易被感知；它不等于所有操作都快了一倍。
```

后者加入解释，需要与上下文和实际任务相符。不是越短越好，也不是每个结果都要补意义。

## 二、新闻标题与作者态度

“某编辑器 3.0 发布，可以接本地模型了”适合突出变化；“这次我最想试的，是本地模型入口”只在作者确有此意图时使用。热情或批评可以有，但不据此造实测或放大范围。

## 三、该保留的不要改

“真正的难点不在模型，在数据清洗。”在区分问题，可保留。
“他原话是‘这个功能我们不会做’。”引用原文不为语气偏好改字。
“厂商测试约 0.3 秒，仅限内部样本。”归因、约与范围不能因精简丢失。

## 四、回复可以短，也可以解释

对方在分享感受时，可接一句“同意，关键是资料能不能带走”；对方在问迁移方案时，就应说明导出、格式和验证路径。没有统一的一行或字数限制。

## 五、进一步定位问题

知识卡 revise-depth、revise-preserve、revise-feedback 分别讨论修改范围、铺垫与作者声音、模糊反馈诊断；按 [knowledge-library.md](knowledge-library.md) 检索。用户只要排版时，保留措辞和语义，改稿例子不构成重写授权。
