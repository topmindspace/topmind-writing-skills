# 风格校准对练（可选）

> 适用：作者觉得通用规则和自己的写法有出入，想把「我喜欢怎么写」变成能复用的规则时。
> 这是一种方法，不是改稿必经步骤。校准结果写进作者自己的私有规则文件（例如工作区里的 `我的写作规则.md`），不改本仓库的共享规则。

## 一、角色

- **AI 出题**：给一个写作场景（开头、结尾、标题、数字、引语、段子反转……），附 2–4 个候选写法。
- **作者答题**：选一个，或都不选自己写一句，再说一句为什么。
- 候选**不标答案、不标「推荐」**，也不按好坏排序，免得作者顺着选。

## 二、一轮怎么走

1. **定范围**：这一轮只练一类场景（例如「长文结尾」），一轮 5–10 题。
2. **出题**：每题写清场景和上下文（前一段写了什么、文体、读者），候选之间只差要测的那一点。
3. **答题**：作者答「选 B，因为……」或「都不要，我会写：……」。只答「认可 / 不认可」的题，追问一句具体改法和理由。
4. **记录**：每题记「场景 / 候选 / 作者选择 / 理由 / 对应的现有规则编号」。
5. **找冲突**：作者的选择和现有规则（`core-voice.md`、`de-ai-rules.md`、lint 脚本）对不上时，单独列一张冲突表：现有规则怎么说、作者怎么选、建议怎么改（改规则 / 加例外 / 只在作者私有规则里覆盖）。

## 三、复测

- 冲突改完后，下一轮用**换过措辞的同类题**复测，看作者的选择是否稳定。
- 两次选择不一致的题，不急着定规则，先问作者哪次更像自己，或保留为「看场景」。
- 已经稳定的规则，后面的轮次不再出同类题。

## 四、整篇验收

几轮之后，用校准后的规则从头写或改一整篇（作者真实要发的稿子），作者通读：

- 读着像自己写的 → 规则可以定下来；
- 哪里不像 → 回到第二步，把那一处当一道新题。

整篇验收比单题更重要：单题都选对、整篇读着别扭的情况很常见（节奏、重复、结尾太整齐）。

## 五、落地

| 结果 | 放哪儿 |
|---|---|
| 只是作者个人偏好 | 作者私有规则文件；改稿时作为「作者样本」优先于通用规则（`SKILL.md`「防过度改稿」第 5 条） |
| 通用写法，别人也适用 | 可以提议改进共享规则；提议时只写方法和虚构例句，不放私人稿件原句 |
| lint 误报 | 记下误报原句的**虚构改写版**，作为脚本的「不应报」回归用例 |

## 六、用数据校准（可选）

对练靠作者的感觉；作者手上有往期帖子的数据（浏览、点赞、评论）时，可以再用数据对一遍：

1. 导出往期帖子（JSONL / CSV），跑 `python3 scripts/post_type_report.py 帖子.jsonl --samples-out 样本习惯.md`，看哪些开头、收尾、类型的相对表现好（按中位数比，样本少的格子别当真）。
2. 把「数据说好、规则却在劝阻」的写法列出来，和作者一起判断：是规则太严，还是只是这个账号的读者偏好。
3. 规则太严 → 提议改共享规则（只写方法和虚构例句，不写数字和原帖）；读者偏好 → 写进作者私有规则。
4. 数据会过时：读者和平台在变，隔一两周重跑一次，结论有变化就更新私有规则。

## 七、注意

- 对练记录是作者的私有文件，不进公开仓库。
- 例句、题目用虚构内容；需要真实素材时用作者已公开发布的内容。
- 每轮结束时让作者看一眼冲突表，确认后再改规则，不要 AI 自己定。
