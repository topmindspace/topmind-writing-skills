# 图源与视觉材料：证据、解释、表达与诚实标注

先判断配图的任务：**一张图把主要变化、适用边界和作者建议讲明白**，还是证明事实、展示真实界面，或者根本无需配图。纯文字已经足够清楚有力时直接交文字，不因缺一张装饰图挡住文字交付。

## 一、按任务选图与核对重点

| 视觉任务 | 合适材料 | 核心设计准则与核对重点 |
|---|---|---|
| **事实与原文证据** | 官方原图、论文原页、代码截图、真实产品界面 | **高亮原文并保留上下文**：框出关键句或参数，保留旁边一两行上下文，**绝不自己重排伪造一张「假论文页/假网页」** |
| **机制、变化与建议（一图流）** | 自制信息图、对比卡片、架构图 | **证据与作者建议视觉分区**：上方/左侧放代码或原文事实，下方/右侧用不同底色或标签放「作者建议 / 适用边界」，不混排 |
| **学术与技术硬核解释** | 学术图表风、干净曲线/柱状/结构图 | 走干净克制的学术/技术图表风，**不加卡通吉祥物或强行卖萌 logo** |
| **概念封面与氛围视觉** | 字体极简封面、概念视觉、生成插画 | 只要涉及产品界面或功能表现而非真实截图，必须在角标或图注标明 **`功能示意，不是实拍`** |

## 二、视觉密度与「简约」的正确理解

1. **避免两个极端**：
   - ❌ **假极简（太空太虚）**：大片无意义留白 + 几个空洞大字摘要，读者点开既看不到证据也拿不走信息。
   - ❌ **硬塞技术长图（太挤太杂）**：把未经核实的细碎参数、大段免责声明全塞进一张手机都看不清的长图里。
2. **追求高信噪比的清晰**：信息集中、层次分明、手机端不用放大就能一眼读完核心数字与对比；简单直观的功能直接用「小标题 + 短例子 + 真实截图」，不画蛇添足做复杂大图。

## 三、诚实标注与边界（防止视觉误导）

- **生成图与概念图**：绝不冒充真实界面截图、实测跑分或官方原图。展示功能概念时明确标注 `功能示意，不是实拍`。
- **旧版界面与示例数据**：引用过往 UI 截图或演示数据时，在图片下方图注简要标明「示例数据 / 旧版界面示意」，不在图片内部硬塞大段免责声明破坏画面。
- **自制数据与对比图**：标明「自制」及数据来源、测试口径。
- **隐私与洁净**：导出后实际打开检查图文顺序、字号可读性与裁切；不把作者私人路径、未脱敏账号信息或无关水印带入成品。参考作品的读序与尺度分析见 [creative-practice.md](creative-practice.md)。
