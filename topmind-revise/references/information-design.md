# 信息设计：结构、密度与图文配合的选项

先想读者读完这篇内容**能拿走什么（一句话判断、一个能照做的原件、还是一个算明白的账）**，再选择承载它的结构与形式。复杂长文写前梳理骨架更省返工；简单短帖理清切口与收尾就能动笔。

## 一、按体裁选结构（是可选工具箱，不是死模板）

不同体裁有不同的高信噪比结构，动笔前先对号入座，**切忌把某一种结构套到所有文章上**：

| 体裁 / 场景 | 推荐结构路径 | 边界与注意事项 |
|---|---|---|
| **1. 经验技巧 / 提示词干货** | **结果/反差数字放第一句** → 可直接复制的原件（提示词/命令）+ 中文大意 → 谁适合用 + **什么时候别用** | 收藏来自「能直接照做 + 知道何时别用」；不先写三段论文背景 |
| **2. 工具 / 插件推荐文（可选结构）** | **标题直接点名插件/工具** → 开头写清安装方式与解决的具体痛点 → 核心功能列表 → 每个小标题配简短例子与真实截图 | **仅适用于工具/插件介绍文**；简单直观的功能展示清楚即可，不长篇大论讲大道理 |
| **3. 产品实测 / 深度评测文** | 核心结论与体感前置 → 按具体观察维度（如延迟、打断、准确率、价格）分节实测 → 真实优缺点与选型建议 | **保留作者个人褒贬与实测数据**；即使全网在「吹爆」，也按具体维度客观展开，不改成「各有优劣」的套话 |
| **4. 规则变化 / 算法开源解读** | 先做通俗定位与核心动作（如「一升一降」）→ 区分「代码参数变化」与「线上实际体感」→ 给创作者的具体建议 | 保留作者主观温度（「仔细聊了一轮，我倒觉得……」），同时守住事实边界，不写成确定性涨粉公式 |
| **5. 新闻发版 / 行业事件** | 最意外的数字、日常体感换算或人物动作反差切入 → 关键变化 `1）2）` → 留一个真问题或停在事实边界上 | 砍掉购买门槛、到货时间、高管全称与发布会感谢辞；查证过程不进正文 |

## 二、可选长文骨架（复杂任务按需使用）

```markdown
# 骨架
类型：（工具介绍 / 实测评测 / 规则解读 / 教程 / 观点随笔）
核心带走物：（读者读完能记住的一个判断，或能直接复制的一件工具/原件）
适用与禁用边界：（谁该用、什么情况下别用）

## 主线安排（按需选填）
| 节 | 核心信息 | 呈现形式（正文/列表/对照/截图/信息图） | 素材与证据来源 |
|---|---|---|---|
| | | | |
```

判断数量、素材比例、自制图数量均**不设硬配额**。材料不支持原设想时随时调整主线。

## 三、图文信息设计：一图讲清、证据与建议分区

当文字需要配图辅助理解时，遵循四条高信噪比原则：

1. **一图流讲清三件事**：一张好的信息图或总结卡，优先把**主要变化、事实边界、作者建议**放在同一张图里讲明白，让读者存一张图就能带走核心信息。
2. **证据与作者建议视觉分区**：图内把「代码参数 / 论文数据 / 官方原文（证据）」与「作者使用建议 / 适用场景（观点）」用不同区块或底色明确分开，不让读者把作者建议误读成官方公告。
3. **高亮原文 + 保留上下文，绝不伪造原页**：展示论文、文档或开源代码证据时，截取真实原图并高亮关键行、保留上下两行语境；严禁自己排版伪造一张看似官方原件的假截图。
4. **正确的「简约」与图表克制**：
   - 既不做「大片空白 + 几个空洞大字」的假极简封面，也不做「塞满未核实细节、手机看不清」的密集长图；追求结构清爽、密度适中、手机端一屏易读。
   - 硬核技术与论文解读采用干净的学术/技术图表风格，不贴卡通吉祥物 logo。
   - 概念封面涉及功能表现时标明 `功能示意，不是实拍`；旧界面截图在图注标明示例数据或版本。

## 四、长度、密度与平台适配

- **篇幅服从信息量**：「短」是砍掉门槛、花絮、报幕和空泛升华，不是砍掉干货原件和必要边界。短帖 100–350 字、公众号与深读长文 1200–2500 字是常见区间，按内容自然伸缩。
- **平台链路隔离**：
  - X 普通帖以纯文本读序为主（段落空行、紧凑 `1）2）`、默认正文无 URL/标签）。
  - 公众号 HTML 与 X Article 富文本支持完整小标题、代码块、表格、安装命令与参考链接。
  - 更多体裁样张见 [creative-practice.md](creative-practice.md)，按需经验卡检索见 [knowledge-library.md](knowledge-library.md)。

## 五、关于 `info_design_hints.py`（I1–I9）

`info_design_hints.py` 仅对连续文字段落、列表对照、首段长度等表面特征提供温和提示（I1–I9），**永远不作为退出失败条件或硬门禁**。叙事、随笔或一气呵成的推演无需为了消除 `I` 提示而硬插图表或拆碎段落。
