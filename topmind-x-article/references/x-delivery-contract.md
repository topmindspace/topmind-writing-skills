# X 文本交付建议

适用于普通短帖、段子、回复及长文派生短帖。X Article 的 HTML 和纯文本导出使用各自平台参考。

## 让结果容易直接使用

默认每条一段可复制纯文本，标签、候选编号和编辑说明在块外。多条帖各自成块；用户只要一条就交一条，不凑固定候选数量。

来源链接、原图和详细查证笔记通常另列，下载入口、报名链接、证据链接等需要随文使用时也可以保留。正文需要的“厂商自测”“据某媒体”“约”“尚未确认”等归因与限定留在正文；它们改变读者对可信度和范围的理解。

thread 每条能接得上，序号和标签位置按读序安排。emoji 与列表样式跟作者习惯，可看 [x-post-format.md](x-post-format.md) ，表情跟作者习惯。

## 简短样张（虚构）

```text
页签新增离线搜索，断网也能找笔记。

厂商在 1 万份笔记上测试，搜索中位耗时约 0.3 秒。免费版可保存一个本地索引。
```

块外可另列“来源：官方更新日志，读取日期”。若这条目标是引导安装，正文末尾可以直接给安装页面。虚构练习里的产品和数字不用于事实稿。

## 图片与授权

图增加证据或理解价值时提供原图或自制图；纯文字成立就交文字，不自动追加“要不要配图”的问题。用户已要求配图时继续完成。生成示意不冒充实测截图。截图注意隐私，素材处理与出处需要时说明，来源和处理方式按图片任务记录。

## 文件与检查

落盘可用 `X短文.txt` 放成稿，`交付说明.md` 放来源、图片与疑点；用户另有结构就沿用。

```bash
python3 scripts/lint_x_post.py 正文.txt
# 用户或交付流程明确要求来源和链接分离时
python3 scripts/lint_x_post.py 正文.txt --separate-links
```

默认文字列表、正文 URL、来源行和段子 emoji 不阻断交付。`--separate-links` 才启用 E10/E11 检查；图片占位、代码围栏等可能误带的标记仍检查。合理的代码、引用等特殊内容需人工判定，不能只因出现符号就断言不可发布。

本库只起草与交付，发布使用获授权的工具与目标。已有明确发布授权不重复索要；没有授权不把写稿扩展为对外发布。
