# x-html-format.md · md2x-html.py 转换规则

`scripts/md2x-html.py` 把 Markdown 原稿转成**单文件 HTML**（内联样式 + 图片 base64 内嵌，
无外部依赖），浏览器打开即用。对标 `md2wechat` 的公众号体验：页顶「一键复制全文」。

## X 文章编辑器语法（调研结论）

以 X 发文工具实测为准（x-md-to-article 等，2026-09-29 调研）：

| 原稿元素 | HTML 输出 | 粘贴进 X 后的表现 |
|---|---|---|
| `#`（首个） | `h1.no-paste`（页面展示） | **不进剪贴板**：手动填入 X 标题栏 |
| `##` / `###` | `h2` / `h3` | X 原生"标题 / 副标题"两级 |
| 段落（`**粗体**`、`` `代码` ``、裸链接） | `p`（strong/code/a 保留） | 原生富文本；行内 code 变纯文本；链接保留 |
| `- ` / `1. ` | `ul` / `ol` | 原生列表 |
| `> ` | `blockquote` | 原生引用块 |
| ``` 围栏（直出提示词） | `div.prompt > blockquote > code` + 「复制提示词」按钮 | 原生引用块。**粘贴流到此为止**：X 不识别粘贴的 `<pre>` 为代码块；读者侧一键复制只能来自 X 原生代码块（Insert → Code 手动建），见下节「提示词的复制链路（双通道）」 |
| `---` | `hr` | 可能被丢弃 → 发布时手动 Insert → 分割线 |
| GFM 表格 | `ul.xtable`（表头加粗首项） | **X 粘贴会丢弃 `<table>`**，转列表保内容；如需原生表格，走 X 的 Insert → 表格手动建 |
| `[图N]` 独占一行 | `<figure>`：内嵌 data-URI 图片 + `[图N]` 编号 + 「下载图片」按钮 | 图片随粘贴带入不稳定，保底按编号下载上传 |
| 封面 `--cover` | 页顶预览 + 下载（`.no-paste`） | 始终在 X 编辑器独立封面入口单独上传 |

「复制全文」前 JS 自动剔除所有 `<button>` 与 `.no-paste` 块（标题、封面预览），
剪贴板里只剩 X 可识别的语义标签：`h2/h3/p/ul/ol/blockquote/a/hr/img`。
工具栏三步话术：**① 标题填入 X 标题栏 → ② 一键复制全文 → ③ 粘贴到 X 正文**。

## 提示词的复制链路（双通道）

核实结论（2026-09-29，两处独立实测一致）：

- X 原生代码块（Insert → Code 插入）**带原生复制按钮**，读者侧可一键复制（编辑器内真机验证，代码内容与复制按钮均保留）。
- 围栏代码**只能**走 Insert → Code 对话框，不依赖剪贴板 HTML 往返；
  粘贴 HTML 会丢弃 `<pre>`（实测笔记，2026-09-07）。

因此提示词的"复制"分两段：

- **通道 A（作者侧，发布前）**：`X长文.html` 里每个提示词块右上角「复制提示词」按钮，
  一键复制该块纯文本。这是你粘贴发布时取用提示词文本的入口。
- **通道 B（读者侧，发布后）**：X 编辑器里把提示词引用块手动转为原生代码块，
  读者才能一键复制。操作（每块约 10 秒）：
  1. 在 HTML 里点该块「复制提示词」（文本已进剪贴板）；
  2. X 编辑器对应位置 Insert → Code，新建原生代码块，粘贴；
  3. 删除原来的引用块（避免正文重复）。
  提示词密集型文章（如 N 条直出提示词）建议逐块转换；纯展示、无需读者取用的代码可跳过。

`X发布稿.txt` 里围栏已去标记、内容保留为纯文本，同样可作为通道 B 的文本来源。

## 图片约定

- 图片来源：有公众号稿可派生时一律用 `--images-from 公众号稿.md`，
  从源 md 的 `![]()` 按文档顺序自动取图；**禁止手工拼 `--images` 顺序**
  （文件名数字排序 ≠ 文档顺序，2026-10-01 九月全景曾因此从第六节起整段错位）。
  无源可派生的纯 X 原创稿才允许 `--images` 手工传参，且须逐张核对。
  脚本内置校验：`[图N]` 须连续编号且数量 = 图片数，否则报错退出。
- `--cover` 只做页顶预览 + 下载，**不占 `[图N]` 编号**
- 配图建议先压缩到宽 900px 左右的 JPEG（单张 <100KB），11 张图总 HTML 约 800KB，
  直接双击打开不卡
- 下载按钮用 JS 取同图 `src` 触发下载，data-URI 在 HTML 里只存一份（体积减半）

## 点击放大（lightbox）

- 正文每张配图、封面预览图均可点击，弹出全屏 lightbox 放大查看原图
- lightbox 内提供「新标签页打开原图」（Blob URL，绕开浏览器对 data: URL 顶层导航的限制）、
  「下载原图」按钮；**刻意不拦截右键菜单**，放大后可右键图片另存，或直接截图
- lightbox 位于 `#article` 之外，「一键复制全文」不会把它带入剪贴板

## 复制行为

- 「一键复制全文」：`ClipboardItem` 同时写 `text/html` + `text/plain`，
  富文本失败时自动降级纯文本
- 「复制提示词」：`innerText`（HTML 实体自动解码，拿到的是干净纯文本）
- 「下载图片/下载封面」：`a[download]` + data-URI，保底链路

## 已知限制（写进发布话术，不要过度承诺）

- 文本 + 格式一键复制可靠（富文本剪贴板，多家 X 发文技能同款做法）
- 图片 data-URI 能否随粘贴带入 X 文章编辑器**不稳定**：
  有成功案例，但更多实战采用"HTML 粘贴文本 + 图片按编号上传"。
  话术固定为："能带入则带入，带不入则按编号下载上传"
- 封面始终在 X 编辑器单独上传（X 有独立封面入口），HTML 里只预览
- 分割线、代码块、表格三类 X 原生块**只能走 Insert 菜单**，粘贴流不承诺还原；
  本链路已做最大兼容（引用块/列表/hr），剩余手动补。
  其中代码块值得手动补：它是 X 侧唯一带读者一键复制（native copy button）的载体，
  提示词类内容建议走「提示词的复制链路」通道 B 逐块转换
