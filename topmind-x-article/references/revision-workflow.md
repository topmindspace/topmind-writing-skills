# revision-workflow.md · 改稿流程（改稿 · 去 AI 味 · 质量三关 · 保真审计）

> **执行者**：装了 `topmind-revise` 时，改稿、质检由它执行（长文技能写完默认调用它的嵌入模式）；没装时，briefs、viral-posts、x-article、wechat-post 按本文件手动走一遍，效果一致。
> 规则来源：`core-voice.md`（场景规则 V01–V33）、`de-ai-rules.md`（结构模式与改写边界）。
> 每一轮都**先备份、记字数**，改完再记一次字数，交付时报「改前 → 改后」。

## 每轮开始

1. **声明**：「技能 · 模式（只审 / 改稿 / 嵌入 / 快审）· 文体（长文 / 短文 / 段子 / 回复 / 标题）」。
2. **备份**：把要改的稿子和配图复制到新的带时间戳目录，不覆盖旧备份。长文文章文件夹固定放 `<文章文件夹>/raw/备份-YYYYMMDD-HHMMSS/`（raw/ 不发布，`check_article.py` 不查；Obsidian 里可以把 raw/ 加进「排除的文件」，免得搜出两份同名文章）；单个短文件放同目录的 `备份-YYYYMMDD-HHMMSS-<稿名>/`。
3. **记改前字数**：`python3 scripts/count_words.py 稿子.md`（去掉 frontmatter、标题行、图片行、空白和 Markdown 符号）。

## 步骤（顺序不换）

| 步 | 做什么 | 完成标准 |
|---|---|---|
| ⓪ 结构 | 先不看措辞：主要信息在不在开头；每节要点能不能一句话说出；哪些并列、步骤、对照、数据写成了段落（`information-design.md` 决策表）；哪里重复、哪里超出篇幅预算；有 `骨架.md` 就对着看。默认只做低风险的结构改动（并列段转列表、对照转表格、删重复段）；重排、拆合章节要 `depth=structure` 或作者同意。随笔类整篇段落是正常的 | 报告「信息设计诊断」写了结论；改了的结构说得出理由 |
| ① 事实 | 承重事实（数字、排名、日期、引语、「第一」）逐条对私有素材来源，上一版里的数字一律重核；有一手信源但未完全确认的热点，短文可直陈加「？！」；纯传闻不写；「第一」核实不了就换说法；引语逐字照录，语气不升级；否定结论换一种查法再查一遍；作者自述 / 回忆类说法要有记录支撑（V13、V22，`fact-check.md`「作者自述与回忆」） | 每条承重事实能在素材来源里找到出处；查不到的列进「未核实条目」交给作者；报告里「人工检查」清单逐项勾过 |
| ② 逻辑 | 结论是否靠前；长文结构「过去一句 + 图、现在汇总加分析、未来判断 + 一条支撑事实」；定性准不准；对比有对象、有定语；同一事实全文同值、同一事物一个叫法（写法也统一，H14）；导语、小结和后文对得上，没有「每个」「都」这类以偏概全；比喻和角色前后一致 | 结构和定性说得出理由 |
| ③ 删冗余 | 删不言自明的引导语、复述图的句子、小节过渡句、无效信息（「暂未回应」「截图为证」）、段段小结。直白但啰嗦的句子只删多余部分，**不整句推倒** | 删掉的每一处都说得出理由 |
| ④ 去 AI 味 | 按 `de-ai-rules.md` 走：强信号见一次就改，弱信号叠在一起才改，语境词按 `core-voice.md` 判断；守改写边界 | `de_ai_lint.py`（短文用 `lint_x_post.py`）的 W 每条有结论；H 只供判断 |
| ⑤ 措辞原则对照 | 按文体抽查 `core-voice.md` 的十条原则和速查表；短文口吻像还在学习的普通人 | 说得出每处改动对应哪条原则 |
| ⑥ 排版 | 长文 Markdown：图紧跟它证明的文字，一段 2–3 句；短文纯文本；段子一句一行；回复一行 | X 稿 E 级错误为 0 |
| ⑦ 保真审计 | `python3 scripts/revise_check.py 改前 改后`：数字、日期、引语、英文专名、确定性词有没有被改；有源稿时加跑 `audit-provenance.py`（段落级）或数字级回源 | 数字、引语的每处变化都有依据 |
| ⑧ 过度改稿检查 | 同上脚本：没有任何 W 命中却被改写的段落占比超过 30% 时提示。事实关、逻辑关、作者意见的改动先登记进改稿报告的改动表（依据写「⓪ 结构」「① 事实」「② 逻辑」「作者意见」），再加 `--declare 改稿报告.md` 跑一次，这些段落单独列出、不计入比例 | 逐段确认或恢复原文 |

## 防过度改稿

1. 每处改动对应一条规则编号或一句作者意见；说不出来就恢复原文。
2. 没有命中的段落原样保留。
3. 作者改过的说法就是标准答案，下次同类位置直接用。
4. 不追求字数一定变短：变短是删冗余的结果，不是目标。
5. 不动：引语原文、专名、术语、讨论某个词本身的句子、作者故意的口语和括号里的自我纠正。
6. 有作者样本时，句长、用词、标点习惯跟样本走。
7. 结构改动依据写「⓪ 结构」加一句诊断；转列表、转表格时原句的事实和措辞照搬，不顺手改写。

## 每轮结束

- 记改后字数，交付时写「字数：改前 N → 改后 M」。
- `revise_check.py 改前 改后 --report 改稿报告.md` 生成报告骨架：改动表已按段落 diff 预填「原文 / 改后」，补上依据；「保留未改的命中」已列出改后稿里全部 W 和 H，逐条写理由；勾完「人工检查」清单；写未核实条目。改稿报告是私有文件，长文放 `<文章文件夹>/out/改稿报告.md`，不进本仓库。
- 需要派生稿（X 长文 HTML、公众号 HTML）时重新生成，再跑一遍检查与图序核对。
- **嵌入模式**（被别的技能调用）：步骤和 revise 完全一样，区别只在交付——对话里只回终稿和三行摘要（字数前后、未核实条数、保留的提示），完整报告照样落盘到 `out/改稿报告.md`，报告头写「模式：embed（调用方：xx）」。用户想看完整报告时直接打开它，不用换模式重跑。
