# X 纯文本帖排版规则（列表 · 缩进 · 换行）

> 适用：`topmind-briefs`、`topmind-viral-posts`、`topmind-format` 的 X 稿，以及 `topmind-x-article` 的 `X发布稿.txt`（纯文本兜底）；`topmind-wechat-post` 在派生 X 稿时也按本文执行。
> 公众号稿不受影响，继续用 Markdown 标题、加粗和列表。
> X 长文的富文本 HTML（`X长文.html`）走 X Article 编辑器的原生列表，以 `x-html-format.md` 为准。

## 为什么要单独排版

X 的普通帖子不渲染 Markdown：`-`、`*`、`1.` 会原样显示成符号，`#` 标题和 `**加粗**` 会把星号与井号一起发出去。
所以 X 稿里没有 Markdown 列表、标题和加粗，列表用 emoji 项目符号，层次靠换行和缩进。

## 推荐符号集

| 用途 | 符号 | 说明 |
|---|---|---|
| 并列要点（默认） | 🔹 | 一级条目的首选，中性、不抢戏 |
| 二级条目 | ▫️ | 与一级配合，缩进两个空格 |
| 步骤 / 先后顺序 | 1️⃣ 2️⃣ 3️⃣ … | 最多 9 条；也可用 ① ② ③（最多 20 条）；更多条目拆成两帖 |
| 结论 / 已确认 | ✅ | 结论、已完成、可用 |
| 对比的另一面 | ❌ | 与 ✅ 成对出现，不单独用 |
| 重点 / 数据 | 📌 📊 | 一帖里最关键的一两条 |
| 提示 / 注意 | 💡 ⚠️ | 小技巧用 💡，需要留意的限制用 ⚠️ |
| 价格 / 福利 | 💰 🆓 | 降价、限免、优惠类 |
| 纯文本替代 | • ▪ → | 不想用 emoji、或语气偏严肃时使用 |

## 使用规则

1. **同帖风格一致**：同一层级用同一个符号。对比用的 ✅ / ❌ 是唯一允许同层混用的组合。
2. **每条一行**：一条一个意思，尽量一行读完（中文约 30 字内），不手动折行。
3. **层级最多两层**：二级条目前加两个半角空格，再接 ▫️ 或 •。X 若吞掉行首空格，改用全角空格（`　`）；仍对不齐就压成一层。发布前在 X 预览里看一眼缩进。
4. **数量适中**：一个列表 3–5 条，不超过 7 条；只有 2 条时直接写成两行短句，不必加符号。
5. **不滥用 emoji**：列表符号之外，点缀表情每帖 1–3 个；严肃资讯、事故、争议类帖子只用 • ▪ 或 🔹，不用 ✅ 🎉 之类的庆祝符号。
6. **语气适配**：干货和数据用 🔹 📌 📊；轻松段子可以多一点表情，但列表符号仍保持统一；英文区帖子也可以用 • 或 → 代替 emoji。
7. **不用 Markdown 语法**：不写 `- ` `* ` `1. ` 列表、`#` 标题、`**加粗**`、`> 引用`、`[文字](链接)`、表格。需要强调就换行前置，或用「」；链接直接贴 URL。
8. **话题标签放最后**：列表之后空一行，单独一行写 `#标签`，不插进列表中间。
9. **留白比符号重要**：开头钩子、列表、来源、标签之间各空一行；一段不超过 3 行。层次先靠空行，再靠符号。
10. **emoji 有分寸**：列表符号选一套用到底；点缀表情（人设 🐔 🐱 🌱 等，见 `emoji-system.md`）放在钩子行或收尾行，正文中间不插；同一个表情不连用（不写 🔥🔥🔥）。

## 来源与核实（X 稿必做）

X 稿也要能经得起追问：每个数字、引用和结论都能找到出处。

1. **先核实再写**：事实来自一手来源（官方公告、更新日志、论文、原帖、财报）；二手报道至少找 2 个独立来源交叉确认，无法核实的承重事实直接删掉。
2. **口径标注**：厂商自报的数字标「（厂商口径）」，未证实的消息标「（传言）」，自己的判断标「（推测）」或写成「现在看起来…」，不和事实混在一句里。
3. **来源行**：正文之后、话题标签之前，单独一行写来源，链接直接贴 URL（X 会自动缩短为 t.co，每条链接按 23 字符计入字数）：

   ```text
   来源：官方更新日志 https://example.com/changelog
   ```

   有多条来源时用 `来源：` 起头分行列出，最多 3 条；更多来源放进评论区或 thread 最后一条。
4. **原帖与截图**：引用 X 原帖时贴原帖链接，截图里写明作者和时间；不贴二次搬运号的链接。
5. **时间锚点**：资讯类写明具体日期（「10 月 13 日」），不写「最近」「近日」。

## 版式骨架（三选一）

| 骨架 | 结构 | 适合 |
|---|---|---|
| 钩子 + 列表 | 钩子一行 → 空行 → 3–5 条 🔹 → 空行 → 一句收尾 → 来源 → 标签 | 更新、盘点、干货 |
| 步骤 | 痛点一行 → 1️⃣–5️⃣ 步骤 → 「简单来说：」一句 → 来源 → 标签 | 教程、上手 |
| 对比 | 一句结论 → ✅ / ❌ 成对 2–3 组 → 适用建议一句 → 来源 → 标签 | 选型、评测 |

thread 每条都按同一骨架：第 1 条放钩子和最关键的事实，最后一条放来源汇总和话题标签，中间条目用「1/5」这样的序号开头。

## 配图与封面（原图优先）

X 短文、短帖的首图按这个顺序取：

1. **一手原图**：官方截图、基准原图、榜单实拍、论文原图、自己的后台截图——有就用它当首图，不另配封面。
2. **没有原图时**：封面可选。用户要，或这条帖子明显需要一张首图时，调用 `topmind-cover` 的「X 短文封面」场景（16:9，1200×675），交付文件 `00-封面-X短文.png`。
3. **纯文字段子**（冷知识、自问自答、吐槽）可以不配图。

资讯和数据类不用 AI 图冒充原图；原图 + 封面合计不超过 4 张。

## 段子体（行间空行）

段子默认段子体：一句一行，行与行之间都空一行；不用列表符号。现成文字转段子体交给 `topmind-format`。
`lint_x_post.py` 对段子体的连续空行不报错。

## emoji 体系

人设点缀（🐔 🐱 🌱 🌸 …）、标题 emoji、列表符号三类的用法与配额见 `emoji-system.md`。

## 公众号稿 → X 稿的派生

同一选题的两个版本，**只允许排版差异，内容一致**：数字、结论、条数、顺序、来源都不变。

| 公众号稿（Markdown） | X 稿（纯文本） |
|---|---|
| `- 要点` | `🔹 要点` |
| `  - 子要点`（缩进） | `  ▫️ 子要点` |
| `1. 步骤` | `1️⃣ 步骤` |
| `## 小标题` | 单独一行文字（必要时加 📌 ） |
| `**重点**` | 去掉星号；需要强调就放到行首或用「」 |
| `> 引用` | 去掉 `>`，引文用「」括起来并写明出处 |
| `[文字](url)` | `文字 url`，或只贴 url |
| 表格 | 拆成“项：值”的列表行 |

## 前后对照（示例为原创）

公众号稿里的写法：

```markdown
## 这次更新的三个变化

- 响应时间：中位数从 2.4 秒降到 1.1 秒
- 价格：输入每百万 token 降 30%
- 限制：单次上下文仍是 128K
  - 超出部分需要分段处理
```

直接发到 X 会变成一堆符号和星号。X 稿写成：

```text
这次更新有三个变化：

🔹 响应时间：中位数从 2.4 秒降到 1.1 秒
🔹 价格：输入每百万 token 降 30%
🔹 限制：单次上下文仍是 128K
  ▫️ 超出部分需要分段处理

数字为厂商口径，实际延迟看地区和负载。

来源：官方更新日志 https://example.com/changelog
```

步骤型写法：

```text
上手只要三步：

1️⃣ 装好命令行工具
2️⃣ 登录并选一个工作区
3️⃣ 把示例文件拖进去跑一遍
```

## 自检与工具

- 清单：无 Markdown 列表 / 标题 / 加粗；同层符号一致；层级 ≤2；列表 ≤7 条；点缀表情 ≤3；数字都有来源行；话题标签在末行；首图已定（原图优先，封面可选）。
- 工具：`python3 scripts/lint_x_post.py X稿.txt` 检查；加 `--fix` 把 Markdown 列表、标题、加粗等自动改成 X 写法（输出到 `--out`，不覆盖原文件）。
  脚本还会警告点缀表情过多（W8）、疑似 AI 套话（W9）、有数据但缺来源（W10）。
  文件里有多条帖子时，用单独一行 `---` 分隔；长文兜底稿（`X发布稿.txt`）加 `--long`。
