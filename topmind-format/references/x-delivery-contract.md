# X 文本交付规约（必读必守）

> 适用：所有产出 X 纯文本的技能——`topmind-briefs`、`topmind-viral-posts`、`topmind-format`，以及 `topmind-x-article` 的 `X发布稿.txt`、`topmind-wechat-post` 派生的 X 稿。
> 排版细则见 `x-post-format.md`，emoji 见 `emoji-system.md`（只用于短文体），版式规律见 `x-layout-patterns.md`。本文只管两件事：**列表与 emoji 怎么用**、**东西怎么交**。

## 一、列表与 emoji：短文用 emoji，段子不用

X 是纯文本，不渲染列表。**两种体裁都禁用 Markdown 列表**（`- ` `* ` `+ ` `1. ` `1)`，`lint_x_post.py` 报 E1 / E2）。

| | 短文体（briefs、格式化成短文、热点短文版） | 段子体（viral-posts 段子、转段子） |
|---|---|---|
| 分点 | **必须用 emoji 列表符号**：🔹（二级 ▫️）/ 1️⃣ 2️⃣ 3️⃣ / ✅ ❌，一帖一套，按 `emoji-system.md` | **不加任何符号**：一条一行，靠行间空行区分 |
| emoji | 标题 emoji 0–1、人设点缀 0–2，按 `emoji-system.md` | **完全不用**：无人设点缀、无情绪表情、无列表符号 |
| 节奏 | 列表条目连续排，长条目间空一行 | 每句、每条都一行，行与行之间空一行 |
| 检查 | `lint_x_post.py 正文.txt` | `lint_x_post.py 段子.txt --duanzi`（出现 emoji 报 W13） |

列表前一行写「xx：」引导语；只有 2 条时直接写成两句。

## 二、交付：正文单独成块，其他各自分开

**正文块 = 只放可以原样发到 X 的内容。** 用户复制整块就能发，不用删任何一行。

| 属于正文块（可发布） | 不属于正文块（另列） |
|---|---|
| 标题行、正文、emoji 列表 | 信源清单（名称｜发布时间｜URL） |
| 正文里的来源行 `来源：名称 URL`（给读者看出处，资讯类默认带） | 原图地址、配图建议、出图 prompt、图注 |
| 话题标签（末行，属正文） | 内部分类标签（类型 / 用途 / 语气）、备选话题标签 |
| 短文体的标题 emoji 与人设点缀 | 排版说明、改了什么、注意事项、核实提醒 |
| thread 的「1/3」序号（每条一块） | 【帖 N】【X 版】①②③ 之类的块标题 |

规定：

1. **一条帖子一个正文块**：聊天里用一个 ` ```text ` 代码块（保证空行不丢）；块里不出现任何上表右列内容，也不出现 Markdown 符号。
2. **多条帖子 / thread**：每条各自一个正文块，不用 `---` 拼在一个块里（`---` 只用于给 `lint_x_post.py` 批量检查的文件）。
3. **块标题写在块外**：「帖 1」「X 版」这样的名字放在代码块上方一行，不进块。
4. **附带信息各自分块，顺序固定**：正文块（一条或多条）→ 信源 → 原图 / 配图 → 内部标签（viral-posts）→ 说明。缺的块写「无」或省略，不糅进正文。
5. **信源块**：每条承重事实一行 `来源名称｜发布时间（注明时区）｜URL`；用户自己的文字写「用户提供，未附来源」。
6. **原图块**：1–2 张，`[图1] 图片地址或交付目录文件名 — 图注；来源`；没有原图写「未找到原图」，并在最后**问用户要不要配图**（可选 `topmind-cover`），不擅自生图。
7. **公众号版**（briefs 双平台）单独一个 ` ```markdown ` 块，不和 X 正文同块。
8. **落盘文件同理**：`X短文.txt`、`X发布稿.txt` 只放可发布内容；信源、配图、说明写进单独的 `交付说明.md`。
9. 发前自检：`python3 scripts/lint_x_post.py 正文.txt`（段子加 `--duanzi`）——E 类清零；W12 表示正文里混进了信源 / 配图 / 说明 / 内部标签，挪出去；W13 表示段子里出现了 emoji。

## 三、聊天交付示例

正例（单条短文；产品与链接为虚构）：

````text
X 正文（直接复制）：
```text
🆕 某编辑器 3.0 发布：补全延迟降到 200ms 内 🐱

这次更新有三处变化：

🔹 补全延迟降到 200ms 内（厂商口径）
🔹 支持多文件同时修改
🔹 免费版每月 50 次

对日常写小脚本的人，免费额度够用了。

来源：官方更新日志 https://example.com/changelog

#AI编程
```

信源：
- 官方更新日志｜2026-10-13 09:00（UTC+8）｜https://example.com/changelog

原图：
[图1] https://example.com/images/release-3.png — 官方发布图；来源：官方更新日志

说明：标题 emoji 🆕 对应「发布」，结尾 🐱 为人设点缀。
````

正例（段子体带分点，零 emoji，两条帖子各自成块）：

````text
帖 1：
```text
这周把发帖流程压缩成三步：

早上先回评论

中午发一条原创

睡前回访新关注

三步走完，不焦虑

#日拱一卒
```

帖 2：
```text
说个冷知识：

收益不只看浏览量。

#创作者收益
```

信源：无（运营段子）
原图：未找到原图。要不要配图？可以用 topmind-cover 出一张 16:9 图。
内部标签：
- 帖 1：类型=打卡日常型｜用途=日常｜语气=温暖
- 帖 2：类型=冷知识揭秘型｜用途=引流｜语气=好奇
````

反例（不要这样交付）：

````text
```text
【帖 1】
这周把发帖流程压缩成三步：🐔
- 早上先回评论
🔹 中午发一条原创
#日拱一卒
配图：风景（日出）· 清新优雅
标签：类型=打卡日常型｜用途=日常
---
【帖 2】
...
```
````

错在：Markdown 列表 `- `；段子里用了 emoji（🐔 点缀、🔹 列表符号）；块标题、配图、内部标签混进正文块；两条帖子用 `---` 拼在一个块里；段子体条目之间没空行。
