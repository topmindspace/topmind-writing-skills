# X 文本交付建议与平台习惯

适用于 X 普通短帖、段子、回复及长文派生短帖。X Article 的 HTML 和纯文本导出使用各自平台参考。

## 一、让结果拿来就能直接发

1. **纯正文独立成块**：默认每条一段可复制的纯文本，说明、候选编号、参考链接和配图说明全部放在代码块外。多条帖各自成块；用户只要一条就交一条，不硬凑固定候选数量。
2. **X 短帖的默认边界与灵活例外**：
   - **默认正文不放 URL 与话题标签**：X 普通短帖正文里挂外链容易影响阅读体验和平台分发，因此默认正文只写工具名、包名或安装命令，来源链接与仓库地址统一放在代码块外另附；话题标签（`#tag`）默认不带，除非特定榜单或活动需要。
   - **场景需要时不作死门禁**：若某条帖子的核心用途就是直接提供报名入口、下载页或随文对质链接，且作者希望留在正文，正常保留即可。切勿把「正文不放链接」外推到公众号或教程长文。
3. **查证过程不进短帖正文，关键归因自然融入**：
   - 核实是作者的基本功，但「谁先爆料、两家媒体口径差几分钟、暂未回应、尚未确认」这类**查证作业过程**放在块外说明，不塞进短帖正文破坏节奏。
   - 影响读者判断可信度的关键归因，用自然人话留在正文里——如「据某媒体报道」「厂商自测」「网上有人反映」，或用真疑问句「某平台被黑了！！？」紧接一句澄清真实范围（「目前是第三方扩展在应用市场被入侵，不是主站源码被黑」）。
4. **只出稿、不擅自外发**：本库只负责起草、改稿与生成本地发布包。即使指令说「发推」「发帖」，默认也是交付可复制成稿供作者确认；没有明确发布操作授权绝不自动调用外部发布接口。

## 二、简短样张（虚构练习）

```text
页签新增离线搜索，断网也能找笔记。

厂商在 1 万份笔记上测试，搜索中位耗时约 0.3 秒。免费版可保存一个本地索引，多库用户得先确认够不够用。
```

块外另附：
- 来源：官方更新日志（读取日期）
- 配图建议：如有真实界面截图可附一张；无合适实测图时纯文字即可直接发。

## 三、图片与图注规范

- **有增益才配图**：一张图能把主要变化、适用边界和作者建议讲明白时提供原图或自制信息图；纯文字已足够成立时直接交文字，不自动追问「要不要配图」。
- **诚实标注性质**：
  - 生成封面或概念图不冒充真实截图，涉及界面时标注 `功能示意，不是实拍`。
  - 引用旧版 UI 或示例数据时，在图注标明「示例数据 / 版本示意」，不在图内硬塞大段免责声明。
  - 自制对比图或统计图标明「自制 + 数据来源」。

## 四、辅助检查工具（非硬门禁）

落盘可用 `X短文.txt` 放纯正文，`交付说明.md` 放来源、配图与待核实项；用户另有目录结构就沿用。

```bash
python3 scripts/lint_x_post.py 正文.txt
# 仅在交付流程明确要求严格分离正文链接与来源行时选用
python3 scripts/lint_x_post.py 正文.txt --separate-links
```

- 默认检查只拦截真正破坏 X 纯文本呈现的残留（如未闭合代码围栏、误带的 Markdown `**粗体**` / `# 标题`、未替换的图片占位符）。
- 文字列表、`？？？` / `！！！` / `！！？` 情绪标点、正文 URL、来源行和段子 emoji **默认均不阻断交付**。`--separate-links` 和 `--strict` 仅作为特定流程的可选开关。
