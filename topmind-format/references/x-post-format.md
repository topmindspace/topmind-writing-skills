# X 普通帖排版经验

普通帖通常原样显示 Markdown 标记；Article 富文本有独立链路。篇幅与媒体限制按账号功能和当前平台核实，本库的长度提示只是编辑参考。

## 可选写法

| 目的 | 写法 |
|---|---|
| 并列 | ·、•、-、🔹 或短段 |
| 步骤 | 1）、1.、①、1️⃣ |
| 对照 | A：… / B：…，✅ / ❌，两个短段 |
| 分节 | 独立标题行、【小标题】、空行 |
| 段子 | 节拍换行、紧凑对话、短段 |
| 强调 | 信息前置、引号、空行、emoji |

列表条数、嵌套和每行长度按信息量决定。引导语能帮助理解时加一句，标题已清楚时直接列。emoji 不是必填，也没有封闭白名单。标点、标签和链接位置跟作者意图走，说明与正文容易区分即可。

## 转换时保留语义

Markdown 加粗可以去星号，标题可以改普通文字；带链接文字可留纯文本 URL 或另列，按用途决定。代码、数学表达式与引用中的符号可能有原意，人工确认后处理。

格式化不改事实、措辞、顺序、必要归因和表达性符号。✅ / ❌、箭头和数字可能承载意义；需要去掉时用等义表达并取得相应改写授权，不能以“只动排版”静默改变。

## 检查

`lint_x_post.py` 的格式残留检查帮助发现误带围栏、加粗等情况；文字列表给 W27/W28，正文链接与来源默认给 W29/W30。它们是选择提示，只有 `--separate-links` 会将链接和来源升为 E10/E11。

`--duanzi` 识别段子体；不因一个表情或紧凑行距判失败。`--long` 用于长文纯文本，`--md` 只查 Markdown 内容。`--strict` 是用户自选的警告门禁，普通写作不需要用它证明质量。更多见 [x-delivery-contract.md](x-delivery-contract.md)。
