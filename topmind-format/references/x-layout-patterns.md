# X 短文版式规律（参考帖拆解）

> 适用：`topmind-briefs`（短文）、`topmind-format`（格式化）、`topmind-viral-posts`（段子 / 短帖）的 X 纯文本稿。
> 本文只记**版式规律**，不收录原文；需要看原样时打开原帖。emoji 一律按 `emoji-system.md` 的 TopMind 体系取，参考帖里的 emoji 只作结构参考。
> 拆解时间：2026-10-14。

## 一、开头钩子

1. **标题行就给结论**：A、F 的第一行把「是什么 + 最扎眼的事实」写全（F 连价格都写进标题），读者只看第一行也拿到信息。
2. **场景钩子**：D 用一个人人遇到过的痛点场景开头（想不起文件名），第二段才说产品——适合工具推荐。
3. **两句短钩**：B 用两句各成一段的短句（判断 + 对比），英文帖常见。
4. 钩子行最多 1 个情绪或标题 emoji（A、E 在行首各 1 个）；F、D 完全不用也照样清楚。

TopMind 写法：短文首行 = 标题 emoji（按关键词对照表，0–1 个）+ 带结论的标题；段子首行 = 钩子句，不加任何 emoji。

## 二、分段长度与空行节奏

1. **一段一个意思**：D、F 每段 1–3 句，中文约 40–90 字；段与段之间一定空一行。
2. **标题、引导语、列表、收尾、标签之间各空一行**；列表内部一般不空行（A、C）。
3. **条目本身很长（超过一行）时，条目之间空一行**（E）——否则手机上挤成一团。
4. 长帖（F）用【小标题】单独一行分节，节与节之间空一行；小标题后紧跟正文，不再空两行。
5. 不出现连续两个以上空行（段子体的行间空行是唯一例外）。

## 三、列表写法

1. **引导语 + 冒号**：「证据拆解：」「关键细节拆解：」「In this video:」——先告诉读者下面是什么。
2. **符号按用途选**：有先后 / 证据链用 1️⃣ 2️⃣ 3️⃣（A）；并列要点用 🔹 或 •（C、E）；一帖一套。
3. **条目格式**：`关键词：说明` 或 一句完整短句；条目开头就是关键词（E 的「商店街：」「夜景氛围：」）。
4. **数量**：短帖 3–5 条最舒服（A 5 条、B 3 条）；C 的 13 条清单体只适合纯吐槽/盘点，干货短文不超过 7 条。
5. **收束条**：E 用一个不同符号标出最后一条「交互」作为收束——TopMind 里改用 📌 标最关键的一条，不在同层换符号。
6. 列表后接**一句总结**（A、E）把读者拉回结论，再接标签。

## 四、emoji 用法

1. 参考帖的 emoji 只出现在三个位置：**标题行首、列表行首、（偶尔）收尾行**；正文段中间都不插。
2. 信息密度越高、emoji 越少：F、D 零 emoji 依然好读，靠的是空行和【小标题】。
3. 不连用、不堆叠；🔥 😍 这类情绪 emoji 是参考帖的个人风格，**TopMind 不照搬**——标题 emoji 只按关键词对照表取，人设点缀用 🐔 🐱 🌱 等（见 `emoji-system.md`）。
4. **段子体完全不用 emoji**：像 D 那样只靠一句一行和空行；分点不加符号。

## 五、中英混排

1. **中文帖里的英文专名保留原文**（Tokenizer、Three.js、EmbeddingGemma、API），首次出现可加中文解释（F：「token（模型处理文字的基本单位）」）。
2. **中英文之间加半角空格**（D、F 的写法：「Mac 上的本地搜索工具」「7.4 亿参数」）；数字与中文单位之间不加空格亦可，但一帖内统一。
3. 中文标点用全角（，。：「」），英文句子内用半角；不在中文句中夹英文标点。
4. 英文帖（B、C）短句、一行一意，列表符号用 • 或 >，不用中文标点。

## 六、链接与话题标签位置

1. **链接单独成段或单独一行**，前面写清是什么：「GitHub：URL」（D）、「Full breakdown: URL」（B）；不把 URL 夹在句子中间。
2. TopMind 规定：来源链接放正文之后、话题标签之前，写成 `来源：名称 URL`（见 `x-post-format.md`）。
3. **话题标签放末行**（A）；E 在标签后又放链接、F 不放标签——TopMind 统一为「来源行 → 标签行」最后两段，标签 0–2 个（段子 1–3 个），不堆 6–10 个（A、E 的堆标签不学）。

## 七、结尾

1. **一句判断或建议收尾**：「免费可薅，别指望质量！」（A 的结构：短句 + 态度）、「装一个能省不少事」（D 的结构：给读者一个行动理由）。
2. 收尾句单独成段，不超过一行；之后只接来源和标签。
3. 清单体（C）可以无收尾，但短文默认要有一句收尾。
4. 短文收尾行可放 1 个人设点缀（🌱 🐾），严肃资讯和段子不放。

## 八、一页速查（写完对照）

- 首行有结论；标题 emoji 0–1 个且对得上关键词
- 段落 1–3 句，段间空一行；长条目之间空一行
- 列表前有「xx：」引导语；一帖一套符号；3–5 条
- 列表后有一句总结或收尾
- 英文专名保留，中英之间空格
- 链接单独一行写清用途；来源行 → 标签行在最后
- 无 Markdown 符号（`- ` `* ` `#` `**` `>` `[]()` 反引号）
