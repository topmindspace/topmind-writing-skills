# 创作方法与样张：加选项，不加禁令

## 怎样开始

有明确任务就完成任务。需要探索时，可以从几条互补路径找方向：读者眼下最关心的问题、作者自己独有的观察、同媒介参考作品的组织方法、库里尚未试过的写法。路径可合并，也可以另想。

先看一个可感知的片段：短帖看完整帖子，长文看标题、开头与一节展开，视觉看实际图片。风格名和抽象形容不能代替作品。选型不明时先用低成本片段探索，不必把每个候选扩成完整长文或调用多次付费生图。

## 实际阅读参考作品

1. 先看用户给的样本、原帖、截图或成品；通过可用工具打开，而不是只读搜索摘要或凭印象描述。
2. 用几句工作笔记记录实际看到的做法：入口、证据安排、叙述距离、节奏；视觉还看读序、尺度、网格和色彩关系。
3. 说明哪些方法能迁移到当前内容。用当前事实重写、重构；参考的虚构数字和第一人称经历不进入事实稿。

看不到时记录访问限制，区分“读了全文”“只读到摘录”“只看到缩略图”。可以用本地样张和已确认材料继续；依赖缺失原文才能判断的事项保留为待核实。不声称看过，也不因一处链接失败停止全部工作。

## 同一素材的三条短文样张

以下均为虚构练习材料，不是真实发布或用户实测：工具“页签”增加离线搜索；厂商测试 1 万份笔记，搜索中位耗时约 0.3 秒；免费版只保存一个本地索引。

### A · 信息直给

```text
页签新增离线搜索，断网也能找笔记。

厂商在 1 万份笔记上测试，搜索中位耗时约 0.3 秒。免费版可保存一个本地索引。
```

适合刚发布、读者先关心“发生了什么”的场景。归因和“约”都是事实的一部分，保留后依然简短。

### B · 场景进入

```text
进地铁后想找昨天的笔记，不用再等网络恢复了。

页签新增离线搜索。厂商测试 1 万份笔记，中位耗时约 0.3 秒；免费版可保存一个本地索引。
```

适合读者不熟悉功能、需要知道它解决什么问题。场景是假设使用情境，不冒充作者亲历。

### C · 取舍判断

```text
页签这次的离线搜索，先解决了“断网能不能找”的问题。

厂商测试 1 万份笔记，中位耗时约 0.3 秒。免费版只有一个本地索引，多库用户得先确认够不够用。
```

适合选型和后续讨论。判断来自免费版限制，没有为“立场鲜明”夸大结论。

三稿事实一致，信息入口不同；不按“更像人”“更有爆款感”预设赢家。

## 两种短帖与回复节奏

虚构段子示范，不作为实际经历或产品行为：

```text
我给待办清单加了个“明天再说”按钮。

现在整个应用只剩这一个按钮有人点。
```

另一种也成立：

```text
待办软件的新功能：明天再说。

需求来自我，使用量也来自我。🙂
```

紧凑对仗和一个表情都可以有效；看笑点、作者风格与场景，不按句式判死刑。

回复“我把提醒关掉后反而专心了”，可以简短接话“同感，少一个红点少一次分心”，也可以追问“你保留了日历提醒吗？我总在这一步拿不准。”第二种只在作者确有这个困惑时使用；否则改成“日历提醒也一起关了吗？”。

## 同一题目的长文结构片段

虚构题目：团队是否该统一使用一种笔记工具。

| 路径 | 开头片段 | 下一节怎样推进 |
|---|---|---|
| 决策备忘录 | “如果问题是查不到资料，先统一索引，再决定要不要统一软件。” | 比较检索、权限、迁移代价；给不同团队条件 |
| 场景叙事 | “周会开了十分钟，三个人还在找同一份方案。” | 从可观察场景追问资料为何分散，再核对替代解释 |
| 逆向检验 | “先假设下周就换成同一工具：谁的工作会更轻松，谁要重做一遍？” | 分角色列收益与损失，再给判断 |

第一种适合快速拍板，第二种适合共同回顾，第三种适合暴露分歧。实际写场景要有材料支撑，不能凭这些示例替作者捏造周会。

## 视觉样张怎么用

封面技能带 `assets/examples/overview.png`，单风格大图若已安装可一起查看。选两张结构差异大的：如巨字与场景、摄影与抽象，而不只是改颜色。长图可以打开现有 HTML 或生成一小段实际预览，观察信息层级和密度。

| 路径 | 可落地小样 | 适合验证 |
|---|---|---|
| 字体 / 极简 | 大字、纯色、留白；没有角色和道具 | 标题是否够准、缩略图是否可读 |
| 原图 / 摄影 | 真素材裁切，文字落在负空间 | 证据与主题、真实氛围 |
| 场景 / 隐喻 | 一项贴题动作，元素数量随需要 | 叙事是否比直陈更有记忆点 |
| 信息 / 图形 | 数据或步骤驱动结构 | 读序、比较与理解成本 |

这些是方案方向，实际小样和最终图仍需要打开看；只写这张表不算已做视觉验证。

## 比较候选与积累经验

少量完整候选可以帮助决策；单条成稿、明确风格或紧急任务，直接给推荐结果。多稿尽量共享事实、受众与篇幅预算，差别放在真正要比较的角度上。

需要评估质量时隐藏版本来源，打乱展示顺序，请作者或目标读者选“更愿意用哪一稿、为什么、有什么仍不对”。保留“无差别”和“各有用途”，不把自评或单次偏好写成普遍提升。复杂任务先小样再成稿，节省成本。

用户要求沉淀经验时，记录“场景—选择—原因—反例 / 例外—证据”，并注明是一次反馈还是多次验证。一次“太素”说明当前作品需要调整，不等于从此禁止纯色底。用户没有要求记录时，当前会话吸收反馈即可，不自动写长期记忆或外传作品。
