# 视觉密度与图文证据设计：一图讲清、证据分区与诚实标注

原创教学与视觉信息设计总结；案例已做通用化脱敏处理，不可充当作者本次任务的亲历或实测事实。

## 一、一张好配图的核心任务：讲清变化、边界与建议

社交平台与长文里的信息图、总结卡，不是为了「给文字凑个装饰」，而是为了**高效率传递结构化信息**。判断一张信息图成不成立，看它能不能在一张图里讲清三件事：
1. **主要变化是什么**（核心数字、机制或前后对比）；
2. **事实边界在哪里**（适用条件、什么情况下不成立）；
3. **作者的具体建议是什么**（读者看完该怎么做）。

## 二、视觉密度的正确理解：拒绝「假极简」与「硬塞长图」

在实际创作中，「简约清晰」经常被误解成两个极端：
- **误区 A（太空太虚的假极简）**：整张图大片留白，只放三五个空洞的大字摘要，读者点开什么干货也没拿到。
- **误区 B（塞满未核实细节的技术长图）**：把密密麻麻的参数、未经核实的传闻细则和大段免责声明全塞进一张图，手机端缩略图根本看不清。
- **正确做法（高信噪比密度）**：围绕核心结论组织 3–5 个关键信息块，字号在手机屏幕上一眼可读；简单直观的功能直接用「小标题 + 简短例子 + 真实截图」，不强行画复杂大图。

## 三、证据与观点分区、原文高亮与诚实标注

### 1. 证据（Evidence）与作者建议（Advice）视觉分区
在制作规则解读、代码分析或论文总结图时，**把「客观证据（代码参数、论文原表、官方公告）」与「作者建议（使用策略、个人推断）」放在视觉上明确区分的区域或卡片里**，避免读者把作者的个人建议当成官方硬性规定。

### 2. 原文截图高亮 + 保留上下文，绝不伪造原页
需要展示论文、官方文档或代码仓库作为证据时：
- 直接使用真实原图裁切，用高亮框标出核心句或关键参数，并**保留上下一两行真实上下文**以证真伪；
- **严禁自己用排版工具伪造一张看似论文原页或官方公告的假截图**。

### 3. 四项诚实视觉标注准则
- **概念封面与生成图**：凡涉及产品界面或功能表现但并非真实截图的封面/配图，必须在边角或图注标明 **`功能示意，不是实拍`**。
- **旧版界面与演示数据**：使用过往版本 UI 截图或 demo 数据说明操作流程时，在图注简要说明「示例数据 / 版本示意」，不在图内硬塞大段免责文字。
- **学术与硬核技术解释图**：采用干净、克制的学术图表与结构图风格，**不添加卡通吉祥物或卖萌 logo**。
- **自制图表**：标明「自制」及数据来源口径。
