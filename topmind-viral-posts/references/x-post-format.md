# X 普通帖排版经验

X 普通帖原样显示纯文本（不支持标准 Markdown 渲染）；X Article 富文本走独立链路。篇幅与媒体限制按账号功能和当前平台规则核实，本库的长度提示只是编辑参考。

## 一、核心排版习惯（清晰、透气、有呼吸感）

1. **按语义段落空行，不句句换行**：
   - 一个完整意思成一段，段与段之间空一行。
   - 废除早期「每句空一行」「每行强控 8–15 字」的碎行做法——除非是极短的节拍段子或群聊对话。
2. **有并列内容时优先用紧凑 `1）2）`**：
   - 当正文确实有 2–5 项并列干货、步骤或回应要点时，X 短帖优先采用紧凑的 `1）` `2）`（或 `·`），行间不插多余空行，一眼扫完。
   - **没有并列内容绝不硬凑列表**：一段话能讲清楚的事，不要为了「排版好看」拆成 `1）2）3）`。
3. **常用形式选项**：

| 目的 | 推荐写法 | 留意事项 |
|---|---|---|
| 并列要点 / 清单 | `1）...` `2）...` 或 `· ...` | 紧凑排列；无并列内容不硬拆 |
| 态度定性 + 变化 | 第一段给带判断的定性，空一行列具体变化 | 避免写成干巴巴的更新说明书 |
| 段子 / 拟人对话 | `人名：台词` 或动作画面分行 | 去掉「某某说：」的叙述累赘，包袱落在最后一句 |
| 强调与节奏 | 核心数字前置、引号、空行、`！！！` / `？？？` / `！！？` / `……` | 力气活跟内容张力匹配，不给平淡稿硬戴 |

## 二、转换与格式化时保留原意

- **清理残留标记，不动作者原意**：将 Markdown 转为 X 普通帖时，去掉 `**`、`##`、围栏标记等渲染残留；带链接文字按场景转为包名/命令或另附链接。
- **严守语义保真**：只做排版转换（如 `topmind-format`）时，不改事实、措辞、语序、必要归因和表达性标点（`？？？`、`！！！`、`！！？`、`……`、`✅ / ❌`、箭头与数字）。

## 三、检查脚本说明

`lint_x_post.py` 帮助发现误带的代码围栏、粗体星号、标题井号等格式残留：
- 文字列表（W27/W28）、正文链接与来源（W29/W30）、情绪标点连用（H2）均为**非阻断提示**，帮助作者确认是否符合当前帖子的意图。
- `--duanzi` 适配段子体；`--long` 用于长推文纯文本；`--md` 仅检查 Markdown 文件。普通创作无需追求「零提示」，更见 [x-delivery-contract.md](x-delivery-contract.md)。
