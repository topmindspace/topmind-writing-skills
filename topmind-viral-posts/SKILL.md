# topmind-viral-posts · X 段子 / 爆款短篇

目标：**短、真、留口子**。读者 3 秒看完，忍不住回一句。示例全部自写，名称和数字虚构。

> **必读（交付格式是硬约束）**：[references/x-delivery-contract.md](references/x-delivery-contract.md)——段子完全不用 emoji；分点一条一行、靠行间空行区分，不用 `- ` `1. `；每条正文是一段可直接复制的纯文本（单独一个 `text` 块），不含 URL 和来源行；链接、图片、内部标签另发。
> **写法**：12 + 2 类的写法见 [references/patterns.md](references/patterns.md)；措辞看 [references/core-voice.md](references/core-voice.md) 的 V19、V26、V29–V40；成稿后按 [references/de-ai-rules.md](references/de-ai-rules.md) 第六节「社交短帖模式」自查。

## 先读：写作原则与信息设计

- [references/social-writing-principles.md](references/social-writing-principles.md)：8 条社交媒体写作原则
- [references/information-design.md](references/information-design.md)：内容 → 形式、篇幅、去啰嗦
- 研究类选题（要查资料、做对比）：[references/research-mode.md](references/research-mode.md)

段子：一个主角、一个画面、一个对立轴；不铺垫，每句都有新信息；人设是还在学习的普通人，可以带一点老司机式的自嘲。

## 类型总表

| 类型 | 特点 | 典型钩子 | 想要的评论 |
|---|---|---|---|
| A1 不懂就问 | 装傻式真疑问 | 难道没人…吗？/ 一直没想明白 | 懂行的人来解释 |
| A2 扒料求证 | 线索 + 上次结果 + 猜测问句 | XX 要上新了？！ | 补线索、猜结果 |
| A3 故障求证 | 第一时间问挂没挂 | XX 挂了吗？ | 「我也是」+ 接梗 |
| A4 卧槽体 | 真实反应 + 换算反差 | 卧槽，算完我人傻了 | 震惊、转发 |
| A5 冷知识 | 我才知道 / 白干了 | 我才知道… | 「我也才知道」 |
| A6 群聊 / 拟人对话 | 每家一句「xx：」 | 今日 XX 群： | 接梗、补一家 |
| A7 连续剧 | 同一主角的连续进展 | 栏目名 + Day N | 竞猜、出主意 |
| A8 算账 / 额度侦探 | 自己的数字换算 | 一个 XX 干掉我 N% 额度 | 晒自己的账 |
| A9 站边轻判断 | 承认一方 + 内行轻判断 | 确实…但… | 两边站队 |
| A10 荒诞自嘲 | 集体痛点写成荒诞画面 | 我以为…已经是极限了 | 共鸣、晒经历 |
| A11 产品反转 | 具体产品 + 场景 + 动作反转 | 一个生活场景 | 接梗 |
| A12 借热点 | 新事套旧梗 | X 版「某某」来了 | 接梗、站队 |
| B1 关系帖 | 互关、新人、打卡、差额冲刺 | 真实进展 | 关注、打招呼 |
| B2 互助帖 | 求码、送码 | 真实需求 | 送码、求码 |

每类的适用题材、钩子、结构、收尾、反例和 1–2 条示例见 [references/patterns.md](references/patterns.md)，旧版 18 类的对照表也在文末。干货类（忠告、技巧、清单）不再算段子，走 `topmind-briefs` 的「观点 / 经验一句话」。

```text
让 Nova 帮我砍掉用不上的订阅

它翻完账单列了三个

我说都退了吧

```

## 标签

详见 [references/tags-and-topics.md](references/tags-and-topics.md)：

- **内部分类标签**：类型、想要的评论、平台、语气。写在正文块外，不进正文。
- **话题标签**：A 组默认不带；要带最多 2 个（宽泛词 + 主题词），放最后一行。B 组关系帖 1–3 个。

## X 纯文本排版

规则见 [references/x-post-format.md](references/x-post-format.md) 与交付规约：

- 不用 Markdown；段子体完全不用 emoji，分点不加符号，一条一行、行间空一行。
- 对话写「xx：」，不写「xx 说：」。
- 自检：`python3 scripts/lint_x_post.py X稿.txt --duanzi`（回复用 `--genre reply`；B 组关系帖加 `--kind ops`，允许行动号召；多条用 `---` 分隔）。

## 有事实的段子

- **先核实再写**：至少两个独立来源；传闻写成求证（问句 +「？！」），不直接当事实写。
- **查证只给自己看**：正文里不写「官方称」「按图估读」「据我查」这类过程，口径提醒放进交付说明。
- **时间点要具体**：「今天上午」「10 月 3 日」，不写「最近」。
- **口径照实**：预告不写成发布，文档里出现不写成上线（core-voice V40）。
- **时效**：扒料、故障以分钟计；超过一天的事要换角度（实测、算账、连续剧），不重复播报。
- 涉及国内厂商：不贬低、不传谣；敏感表述先和用户确认（core-voice V21）。
- 要写成正式快讯、新品、榜单 → `topmind-briefs`。

## 何时不用

- X 长文、发 X 文章 → `topmind-x-article`
- 公众号文章 → `topmind-wechat-post`；快讯、新品、羊毛、榜单、论文、观点短文 → `topmind-briefs`
- 现成文字只要转段子体 → `topmind-format`（只排版不改字）
- 只要封面、头图 → `topmind-cover`；长图、海报 → `topmind-poster`
- 单独改一条现成的帖子、去 AI 味 → `topmind-revise`（`mode=quick genre=duanzi`）
- 把帖子发到 X → `topmind-x`（须用户确认）

## 写作要点

1. **先定想要哪种评论**：想要老手来解释，就把自己放在没搞懂的位置；想要读者接梗，就留一个没讲完的画面；想要两边吵，就给一个对立轴。
2. **开头**：一句真实反应或一个真困惑；情绪后面马上跟一个具体事实（卧槽 + 数字），只有情绪的一句话不行。
3. **问句**：真问题开头、结尾都可以（懂行的人能给出具体答案的就是真问题）；带自己立场或押注的选择题也可以。套路互动钩子不用：「你会换吗？」「你们怎么看？」「评论区聊聊」「你还知道哪些？」。
4. **结尾**：用「...」留口子，或一个具体动作反转；不升华，不金句。写完做删尾测试：删掉最后半句更好就删。
5. **口语、简单**：说人话；精炼不等于砍字，「修好」不缩成「修」；中文帖不夹没必要的英文术语。
6. **具体数字**：给明确的比较对象；作者自己的数字必须是真的，不编。
7. **不用排比、不铺陈**：太整齐的金句和对仗读着像 AI；像随口吐槽。
8. **不编经历**：「我」做过的事只能来自作者给的素材；没有就换个写法，或在交付说明里提示「这条适合你讲自己的经历」。
9. **成稿后自查**：de-ai-rules 第六节 S01–S10；lint 的 W 警告每条要有结论，H 提示只供判断。

## 回复与转发点评

按 core-voice V29、V30、V37：

- **回复是聊天，不是点评**：越短越好，中文默认 25 字以内，可以只是一个词组；态度放第一个字。
- **不复述原帖**：删掉和原帖重复的词，剩下的才是你的东西；剩不下就只写态度。
- **不套类比**：「跟…一个道理」「X = Y」「说白了」这类换成自己的做法或一个具体场景。
- **不把推理说完**：点到就停，后半句留给对方。
- **不写总结腔**，不写英文网文模板句，不编经历。
- **要加深度**只加帖子外的东西：自己的经历（有记录的）、一个数字、一张截图、一个好玩的真问题。
- **交付两条备选，要真的不一样**：一条一两个词的态度，一条经历或真问题；都没把握就写「这条点赞就行」。
- **转发点评**：先给态度，再放一行干净的事实，用「...」「？」「！！」收；不复述更新内容。
- 自检：`python3 scripts/lint_x_post.py 回复.txt --genre reply`。

## 配图

**按类型定**（详见 patterns.md「配图」）：段子和吐槽默认纯文字，图本身就是爆点（翻车截图、跑分对比、扒到的代码、账单）才配；关系帖可以配自己的主页或后台截图。

需要配图时的优先级：

1. **官方原图第一**：发布会截图、官方博客配图、GitHub README 图、产品截图
2. **第三方原图第二**：权威媒体资讯图、原帖截图（注明来源）
3. **AI 生图兜底**：只有两种情况用——
   - 关系帖（互关 / 打卡 / 新人报到，没有具体新闻事实），且用户同意
   - 有事实但找不到可用原图

**生图风格**：清新优雅 或 商务美观 MD3 风格（Material Design 3：干净留白、柔和圆角、克制配色）。
不搞暗黑炫酷，不搞油腻网红风。

**图库匹配**（仅 AI 生图时用）：

| 图库 | 适用类型 | 出图要点 |
|---|---|---|
| **美女** | B1 关系帖（互关 / 新人） | 吸睛但不低俗，自然笑容，生活感；避免过度修图网红脸。尺度两档：默认清纯吸睛；性感档（大学生穿搭 T 恤/热裤/吊带、苗条曲线突出、近距离特写）按用户要求选用 |
| **宠物** | B1 关系帖 | 猫为主，狗 / 鸟点缀；表情生动、有故事感 |
| **风景** | B1 打卡 | 日出/远眺/星空，配"坚持""远方"意境；清新优雅风 |
| **奇幻** | A10 荒诞自嘲（用户要图时） | 异星风光、奇特地貌、超现实；反差萌，引发好奇 |
| **标语** | 用户明确要文字图时 | MD3 商务风：金句一行 + 浅色底 + 深色字；字少而大 |

**人像生图提示词公式**（目标：自然、清爽、有生活感，不像 AI 图）：

```
Photorealistic portrait, 35mm film photography aesthetic, shot on 85mm lens f/1.8, subtle film grain:
a stunningly beautiful young Chinese woman in her early 20s,
pure innocent look, big clear bright eyes, soft natural makeup,
flawless porcelain skin, sweet gentle smile, long silky black hair,
slender graceful figure,
[场景 + 服装 + 举牌/动作], soft golden-hour / window light,
clean uncluttered background, vertical 9:16
```

要点（都来自实际使用中遇到的问题）：
- **只用正面描述**：写"flawless porcelain skin"，不写"no AI face / natural skin texture"——否定词会被理解成"往脸上加点瑕疵"，雀斑痣就是这么来的
- **美貌必须给具体锚点**："beautiful"太抽象，要拆成"大眼睛/清澈眼神/淡妆/柔顺长发/干净气质"，清纯才落得下来
- **真实感靠相机语言**："35mm film + 85mm f/1.8 + film grain"比任何"不要AI感"都管用，给模型一个物理介质参照
- **环境做减法**：干净背景 + 柔和自然光；"candid snapshot/抓拍感"会把质感拉回路人随手拍，只在用户明确要生活流时用
- **身材要显式写**：不写就只拍大头照；"slender graceful figure" + 得体服装（白裙/亚麻衬衫/针织衫），吸睛不低俗

**配图流程**：
1. 写完先判断这条要不要图（按类型）；要图先找原图（官方 > 第三方 > 原帖截图），给 1–2 张图片地址与来源。
2. 没有原图 → 先问用户要不要配图；同意后按上表选图库，走 topmind-cover 的「X 短文封面」场景出图，不擅自生图。
3. 尺寸：X 单图 1200×675（16:9）；多图也可用 1:1；合计不超过 4 张。
4. 检查：图与文案情绪一致，不抢戏，不低俗；原图不裁掉关键信息；截图里他人的信息打码。

## 工作流

1. **定位**：这条想让哪种人来评论？据此选 A 组或 B 组的一个类型（见类型总表）。
2. **取写法**：从 `references/patterns.md` 取对应类型的钩子、结构、收尾，对照反例。
3. **写**：一个主角、一个对立轴；段子体排版；有事实的先核实。
4. **配图**：按类型判断；要图先找原图，没有就问用户。
5. **自检**：删尾测试；de-ai-rules 第六节；`scripts/lint_x_post.py --duanzi` E 类清零（含 E10 URL、E11 来源行、E12 配图说明），W 每条给结论；用户要改稿时转 `topmind-revise`（`mode=quick genre=duanzi`），没装就按 `references/revision-workflow.md` 手动走。
6. **交付**：一次 3–5 条让用户挑，类型错开，严格按 [references/x-delivery-contract.md](references/x-delivery-contract.md)。

## Output Contract

- 3–5 条独立短帖，每条通常 3–6 行，默认段子体；**每条正文单独一个 `text` 块**（块名「帖 N」写在块外），块里只有正文（和可选的末行话题标签），没有 URL、来源行、配图说明。
- 正文块之后依次另发：**链接**（每条一行「名称｜发布时间｜URL」，没有写「无」）→ **图片**（地址 + 来源；纯文字写「不配」；没有原图写「未找到原图」并问要不要配图）→ **内部标签**（类型 / 想要的评论 / 平台 / 语气 + 备选话题标签）→ 需要时加 **口径提醒**（哪些是传闻、哪些数字是厂商口径，给作者看，不进正文）。
- 段子零 emoji。
- 不编造用户数据：粉丝数、收益、用量等数字用户给才写。

示例（原创，数字与名称为虚构）：

````text
帖 1：
```text
我才知道，Nova 的深度模式是每一轮单独计费的

我开着它聊了一整天

白干了？
```

帖 2：
```text
今日模型群：

青鸟：新版本上线了，价格没动

Nova：我们也上线了，价格动了

用户：我只想知道今天哪家不排队
```

链接：无
图片：帖 1、帖 2 不配（纯文字段子）
内部标签：
- 帖 1：类型=A5 冷知识｜想要的评论=共鸣｜平台=X｜语气=自嘲幽默｜备选 无
- 帖 2：类型=A6 群聊｜想要的评论=接梗｜平台=X｜语气=自嘲幽默｜备选 无
口径提醒：帖 1 的计费规则发前再核对一次官方说明。
````

## Operating Rules

1. **不碰政治、色情、医疗建议**。
2. 中文区风格，不硬翻英文 meme。
3. 关系帖不承诺做不到的事（「必回关」写成「评论我都会回」，除非用户明确）。
4. 人像图不低俗：自然、生活感、有笑容；用户明确要「流量向」时再放开。
5. 宠物图猫优先，外星 / 奇幻图取异星风光和奇特地貌。
