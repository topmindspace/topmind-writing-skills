# 公众号写作质量经验

事实、逻辑与表达相互支持。按任务规模选择核查动作，口吻可参考 `core-voice.md`，改稿方法看 `revision-workflow.md`。

## 事实与证据

优先核承重数字、日期、排名、状态和引用。厂商自测、媒体转述、估读与推断明确区分；“我认为”可以表达主观立场，不用问号遮住未确认信息。

核查常见问题：不同版本数字混用、每月误写每年、压缩值与原始值直接相除、主体同名混淆、预测当成已发生。查不到时也检查搜索范围和功能名是否正确。已有可靠、仍适用的来源可复用。

## 逻辑与结构

选择与读者相符的主线，结论、证据和反例各有位置。重要争议主动看反证，单一事实说明不强塞反方；关联不等于因果，单个案例不代表行业。

## 文字与节奏

先通读，找具体的理解困难、重复与声音偏差。可以删引导，也可以保留必要铺垫；问句、对仗、排比、第一人称和术语看具体作用。有效表达无须因为命中词表而改写。

```bash
python3 scripts/de_ai_lint.py <稿>.md
python3 scripts/scan_ai_flavor.py <稿>.md
python3 scripts/scan_ai_flavor.py --which
```

扫描器只量词面 / 模式。85 分不是定稿门槛，满分不证明质量，低分也不证明稿子不好；清单、引用和专业文本尤其需要语境判断。需要检查来源时 `--which` 可确认是否使用外部扫描器；不因写稿自动配置或调用外部服务。

改稿保留事实、引用与确定性，作者未提供的经历和数字不补造。用户要全面改写可以重组和扩写必要解释；有证据的事实修正说明依据。代码和配置按实际目的保留，语言流畅不能改变其可执行含义。

文件改动串行核对，避免覆盖；复杂稿用 `revise_check.py` 检查事实变化，但没有命中 W 的段落也可合理修改。成效由读者理解和作者认可验证，不能以警告减少或字数下降代替。
