# 发文铁律：精炼客观 + 素材优先 + 研究深度

> 适用于 topmind-briefs / topmind-x-article / topmind-wechat-post。
> 触发技能时默认执行，无需用户每次声明。

## 一、默认写作模式：精炼客观

1. **文字精炼**：能一句话说清的不用两句；删一切"正确的废话"。
2. **陈述客观事实**：只写可核实的事；厂商数字标"厂商口径"；无法核实就删。
3. **不泛化**：不从单个案例跳到"行业趋势"；不从一次测试跳到"彻底改变"。
4. **不主观判断**：不写"令人惊艳""颠覆性""必看"这类无法验证的形容词。
   让事实自己说话。
5. **标题问句**：当核心判断尚未完全确定时，标题可用问句诚实表达不确定性
   （例：《一切皆插件之后：软件工具的 RSI 时刻？》），正文用证据把"问号"讲透，
   而不是用感叹号假装确定。

## 二、素材优先原则

1. **信息收集**：基于用户要求，做全面的信息和素材收集、整理、交叉比对核实。
2. **原图优先**：官方图表、第三方榜单、数据表格——尽量用原图，不手绘仿制。
3. **图说事实**：能用素材图片传达的意思，文字就少写。图承担数据，正文只解读。
   看图即知的事实（数字、趋势、结构）正文不再复述一遍，只写图看不出的解读和判断。
4. **素材排序**：官方产品截图 > 官方基准图 > 第三方榜单截图 > 权威媒体图表 > 自制图表。
   自制图只用于时间线、价格对比、总结盘点（无法找到原图时）。
5. **配图丰富度（主动挖掘）**：不要等"有图就用"，要主动找图——论文原图/图表、
   工具截图、评测基准原图、关键帖子截图、产品界面实拍。有信息量的段落尽量配图，
   装饰图一律不要。目标：读者看图能跟上 70% 的论证，文字负责剩下的 30%（判断与连接）。

## 二点五、可视化优先（写作铁律）

> 能用可视化传达的，不用文字啰嗦。这是 X 和公众号共同的内容要求。

1. **表格 > 段落**：对比类内容用简单表格，不写大段文字。
2. **列表 > 段落**：并列要点用列表，不写成长段。
3. **"概要 + 列表"**：信息密集的节，先给一句概要（这节的结论），再用列表展开论据。
   不写长段论述；非写不可的长段，拆成多个短段或转成"概要+列表"。
4. **图表 > 描述**：数据趋势用图表，图片用素材原图。
5. **卡片样式**：MD3 优雅风——不用任何衬条（左侧色条、顶部/底部横向线一律不用）；
   靠背景色调（tonal）+ 大圆角区分层级。表格用浅色风格：表头浅蓝底 + 蓝色文字，
   无网格线，行间用底部分隔线；宽表转卡片时同样浅色、无衬条、标题用蓝色强调。
6. **文字密度**：每段 ≤110 字；列表项 ≤70 字；健康密度 300-450 字/图。

## 三、研究探讨模式（用户做研究/思考时）

当用户给出主题 seed、问题、思考、启发、线索，要求探讨分析时：

1. **充分收集**：信息收集、整理分析、检索比对，一个都不能少。
2. **客观为基**：所有论述建立在核实过的事实上。
3. **主观有度**：可以有针对性的主观论述、论点、判断、分析——
   但必须：不肤浅、洞察深入、严谨、有思考、有全面性/系统性、
   角度有特点、有判断力。
4. **留白提问**：可以提出合理的问题留待后续交流或跟进；可以合理挑战既有观点。
5. **论文扩展**：有条件时，寻求高质量论文、研究报告，进一步分析扩展。

## 四、禁止清单

- ❌ 泛化扩展：从个案跳到全行业
- ❌ 主观陈述：无法验证的形容词和判断
- ❌ 编造数据：任何未经核实的数字
- ❌ 套话：正确的废话、社交垫词
- ❌ 浅层分析：只复述事实不给洞察（研究模式下）

## 五、措辞偏好（2026-10-02 用户亲口，插件化/RSI 一文改稿确立）

用户对"AI 味"的判断标准：不是词汇黑名单，而是**强断言、伪简洁、评论腔**。以下全部是用户亲手改过的实例，照做：

- **不用噱头式导语**：❌"两条帖子，一个判断" → ✅"看他们的互动讨论有了这样的感觉："。平实描述代替 clever framing。
- **不用"一句话"式伪简洁**：看上去简洁实际不舒服。→ ✅"简单来说"/"简单总结"，或干脆删掉。
- **不用绝对化断言**：❌"争的从来不是插件化对不对，而是…" → ✅"现在看起来，争的不是插件化对不对，而是…"。❌"真正的 RSI 得…" → ✅"RSI 最关键的可能还是得…"。去"从来"、去"真正"，留余地。
- **"我的判断"→"现在看起来"**：弱化主观断言，不摆评论家姿态。
- **"全文的题眼"→"原话中最关键的一句"**：不搞评论腔。
- **"同一份报告"→"报告中 XXX"**：指代词累赘，直接说。
- **"坑"→"挑战"/"问题"**："七个坑"改"七个挑战"。"坑"字不舒服。
- **删自以为有趣的梗**：❌"弧线很经典"——没人看得懂还尴尬，直接删。
- **避免强烈描述词、强转折词**：不堆"最""极""颠覆"，转折能弱则弱。
- **"很老"→"可以追溯很早之前"**：❌"谱系很老" → ✅"谱系可以追溯很早之前"。"很老"口语化 AI 味，改书面化。

总原则：**断言留余地，简洁不取巧，评论腔删掉**。用户改过的说法就是标准答案，下次同类位置直接用改后版。

## 六、工作区规约与交付标准

> 以下为 topmind 工作区默认规约；其他用户可通过环境变量或 CLI 参数覆盖，
> 技能本身不强制依赖特定目录结构。

1. **目录规约（默认）**：公众号+X 创作包放在工作区的长文类专题下（按类别**名称**找「长文」，
   兼容旧名「创作」「专题」；专题默认 `{当年}-公众号`），正式稿 HTML 交付到 role:delivery 类别
   （以工作区 `topmind.yaml` 的实际目录为准，例如 `88-输出/`）。编号与年份不写死。
   覆盖方式：`--base` 参数 > `TOPMIND_WECHAT_BASE` > `TOPMIND_WORKSPACE`（按名称发现类别）；
   都没有就报错要求传 `--base`，不猜惯例路径。详见各技能 SKILL.md 的"路径默认"节。
2. **云端备份**：所有文章创作结果默认在云端工作区按规约格式目录备份存档，
   方便找回/暂存。
3. **封面默认 2 版**：每篇长文默认提供至少 2 版不同风格 cover 供用户选择。
4. **双平台同步**：默认 X + 公众号双版，不分长短文。

## 七、研究深度要求（用户给定主题）

1. **全面调研**：外部调研、分析、研究、信息收集、素材整理、事实核对、
   交叉比对、来源确认，一个都不能少。
2. **深入分析类**：研究业界论述、讨论、观点、判断、论文、新闻、研究报告，
   多方信息综合后，再做系统性全局性的文章架构和内容撰写。
3. **完成后核实**：成稿后做深度核实和交叉比对，确保素材、信息、案例、
   图片、图表、三方资源尽量丰富准确。

## 八、表述偏好：客观无偏见

1. **无偏见歧视**：不带偏见和歧视，尤其是对中国和国内相关表述尽量正面积极。
2. **敏感言论**：涉及敏感言论如无法确定，先和用户讨论再定稿。
3. **信息汇总类**：尽量用客观官方、三方原图、图片、数据表、图表阐述观点，
   文字作为补充，简单精炼。
