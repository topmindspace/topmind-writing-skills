# de-ai-rules.md · 去 AI 味模式表（按需诊断）

> **什么时候读**：成稿后自查、改稿（topmind-revise）时读。写的时候按第 0–2 层的正向写法写（`social-writing-principles.md` → `information-design.md` → `core-voice.md`），不对着本表写：盯着一张「不要写什么」的表写稿，注意力会落在避开词上，而不是读者要什么。
> 适用：topmind-briefs / topmind-viral-posts / topmind-x-article / topmind-wechat-post 成稿后自查、topmind-revise 改稿；topmind-format 只报告命中、不改字（用户要求改写时转 topmind-revise）。
> AI 味多半来自**句式和结构**，换掉几个词不够；更根本的是没想清楚要传达什么、没站在读者那边。下面先按根因看，再查具体模式。
> **脚本**列：`W9` `W14`–`W21` = `scripts/de_ai_lint.py`（`lint_x_post.py` 复用）会报警告；`H` = 只提示；`人工` = 脚本查不准，靠通读。
> **信号**列表示复查优先级：强、弱、语境都不是自动改写指令。每个命中看具体内容；有效修辞、必要归因和作者习惯都可保留。改法列提供尝试方向，不是替换表。

## 一、改写边界（先守住，再动手）

1. **只改表达，不改事实**：保留数字、日期、专名、引用和链接的事实含义；有证据的事实修正可做并说明。
2. **确定性不升不降**：原文「可能」不改成「一定」，「已发布」不改成「据称」，「计划」不改成「完成」。
3. **不编**：不为了「像人」加经历、对话、情绪、第一人称或口头禅；原文没有的细节，宁可空着。
4. **术语不换**：专业词、产品名保持原样，不为了避免重复换同义词。
5. **模式是线索，不是黑名单**：每个命中回到上下文看，确实空泛、重复、有歧义才改；有效段落可以保留，也可因用户授权的结构与节奏目标调整。
6. **何时不改**：引语原文、专名、讨论这个词本身的句子、作者故意的口语和细节、括号里的自我纠正。
7. **有样本就跟样本**：有作者以前的稿子时，句长、用词、标点习惯跟样本走，优先于本表。
8. **改完回读**：重要改动能说明对读者或作者目标的益处，无需命中规则编号。分数、字数下降不能代替语义核对。

## 五、社交短帖模式（S01–S10）

前四节主要从长文归纳。短帖、回复、段子的 AI 味来自另外两处：**没有自己的位置**（复述、总结、中间立场）和**太完整**（推理说完、金句收尾、结构工整）。下面的典型样子都是自写的。

| 编号 | 模式 | 典型样子 | 改法 | 脚本 |
|---|---|---|---|---|
| S01 | 复述原帖 | 回「某工具免费了」：「免费这点太香，以后剪辑软件要变文物了」 | 删掉和原帖重复的词，剩下的才是你的东西；剩不下就只写态度 | 人工 |
| S02 | 类比腔 | 「跟带新人先给手册一个道理」「说白了」「本质上」「X = Y」 | 类比有效就保留；不贴切时尝试具体场景 | W24（reply / duanzi） |
| S03 | 把推理说完 | 「…是不是重置完大家一起猛用，看着就像砍了啊？」 | 点到就停，后半句留给读者 | 人工 |
| S04 | 安全中间立场 | 「各有优劣，看场景吧」 | 有证据则鲜明，有真实条件则讲条件，不为互动硬造立场（V36） | 人工 |
| S05 | 编经历 | 「我的土办法是…」（作者没做过） | 只用作者给的素材；没有就在交付说明里提示作者自己讲 | H16（reply / short） |
| S06 | 套路互动钩子结尾 | 「你会换吗？」「评论区聊聊」「你们怎么看？」「你还知道哪些？」 | 邀请有具体目的就可保留；无助于交流时删减或问得更具体（V34） | W22（short / duanzi） |
| S07 | 播报模板 | 警报 emoji +「重磅 / 突发」+ emoji 分点 + 一串话题标签 | 第一句给个人反应或最狠的一个数 | H19（short） |
| S08 | 二手叙事 | 「海外大号都在刷…」「大家都在说」 | 给自己的判断或一手信息 | 人工 |
| S09 | 工整三板斧 | 「快、稳、省，一个都不少」「它写稿，我挑刺」 | 留一个具体事实 | H5 / W9 |
| S10 | 英文网文模板 | bingo card / Step 1… / apparently / your move / not complaining | 3–6 个词的普通网友说法 | W25（reply，英文） |

几个配套判断：

- **删尾测试**：把最后半句删掉读一遍，删掉更好就删。
- **想要哪种评论**：动笔前先定（解释补充、接梗、站队），留对应的口子；什么口子都没留的帖子，通常就是「太完整」。
- **口径词**：“官方称”“按图估读”可能直接影响读者判断，保留必要归因和误差；纯查证过程可另列（V39，H17）。
- **英文小词**：credits、quota、changelog 等按读者背景选择原文或中文（V38，H18）。
- **段子体行间没空行**：可按节拍留白，也可保留紧凑对话；W23 只是行距现象（duanzi）。
- **回复太长**：中文回复超过旧参考线时提示（H15 / W26）；复杂交流可以展开，不设通用长度上限。

## 六、怎么跑

```bash
python3 scripts/de_ai_lint.py 稿子.md                    # 长文 Markdown：W9 W14–W21 + H 提示
python3 scripts/de_ai_lint.py 短文.txt --genre short     # 文体：long / short / duanzi / reply / title
python3 scripts/lint_x_post.py X稿.txt                   # X 短文：格式 E 级 + 同一套去 AI 味检查
python3 scripts/lint_x_post.py 段子.txt --duanzi
python3 scripts/lint_x_post.py 关系帖.txt --duanzi --kind ops   # 关系帖允许行动号召（W22 豁免）
python3 scripts/lint_x_post.py 快讯.txt --genre short --kind news # 快讯首行超 30 字才报 W10
python3 scripts/lint_x_post.py 稿子.md --md              # 兼容旧用法，等同 de_ai_lint.py --genre long
```

- **E 格式问题**：检查是否误带标记或实际破损；特殊引用、代码按语义判断。
- **W 警告**：看上下文是否有实际问题；合理写法可保留，无需逐条写申辩。不要求清零，简单稿件无需额外报告。
- **H 提示**：只列出，按 `core-voice.md` 的场景判断要不要留；不计入 `--strict`，`--no-hints` 可以关掉。
- 脚本刻意收窄，宁可漏报也不误报；「人工」列的模式靠通读。三个自查办法：**朗读**（拗口、像念稿就改成口头会说的话）、**删句**（删掉不影响信息就删）、**替换**（把产品名换成别的句子照样成立，就是空话，换成只属于这件事的细节）。
- **讨论词本身、展示反例不报**：「」“”里的短词（「一文读懂」「我认为」）只是在说这个词；以「改前：」「原文：」「反例：」「A：」「B：」开头的行是在展示别的写法。这两类不参与词面和句式检查，段长（W14）照查。
- **长文 Markdown 另有两条提示**：H13 小标题格式（有的写序号有的没写、一个小标题里标点叠在一起，V06）；H14 同一个中英混排说法有带空格和不带空格两种写法（标题受文件名限制时在报告里说明即可）。
- 段长（W14）的字数口径和 `count_words.py` 一致：去掉空白、Markdown 符号和链接地址后的字符数。
- **长文 Markdown 还会附带 I 级信息设计提示**（`info_design_hints.py`，I1–I9：连续纯文字、图表列表少、可转列表 / 表格、重复、首段没交底、长节全是段落、超篇幅预算、素材罗列）。它们和 W / H 分开显示，只供判断，永远不进 `--strict`；`--no-design` 可以关掉。判断方法见 `information-design.md`。
- 规则回归测试在仓库根目录的 scripts 下（`test_lint_rules.py`，会一起跑 `test_info_design.py`）：一组「不应报」的写法，任何一句被误报，CI 就失败。

## 从诊断回到创作

本表用于定位可能的问题，不是写作许可清单。需要替代方向和完整例子时按 [knowledge-library.md](knowledge-library.md) 查相关知识卡；修辞、客套、铺垫、情绪和重复均看作用。排版与引用保真按对应工具协议处理，不为“去味”改坏事实或作者声音。
