# revision-workflow.md · 固定改稿流程

> 适用：用户要求「改稿 / 精简 / 去 AI 味 / 按我的意见改」时，briefs、viral-posts、x-article、wechat-post 一律按这个顺序走。
> 每一轮都**先备份、记字数**，改完再记一次字数，交付时报「改前 → 改后」。

## 每轮开始

1. **备份**：把要改的稿子和配图复制到新的带时间戳目录（如 `backup-YYYYMMDD-HHMMSS-<稿名>/`），不覆盖旧备份。
2. **记改前字数**：去掉空白、图片行、标题行后的字数（下面的命令）。

```bash
python3 - <<'PY' 公众号稿.md
import re, sys
t = [l for l in open(sys.argv[1], encoding="utf-8").read().split("\n") if not l.startswith(("![", "#"))]
print(len(re.sub(r"[\s*\-#>\[\]()`]", "", "".join(t))))
PY
```

## 四步，顺序不换

| 步 | 做什么 | 完成标准 |
|---|---|---|
| ① 逻辑与事实 | 结论是否在开头；结构是否对（如「过去最短、现在汇总、未来有判断」）；每条承重事实回一手来源，上一版里的数字一律重核；厂商数字标「厂商口径」，传言标「传言」，查不到的删掉或交给用户决定 | 每条事实能在私有信源清单里找到来源 |
| ② 删冗余 | 删复述、删铺垫、删看图即知的数字；长句拆短；能用原图说明的只留一句引导 | 改后字数通常明显少于改前 |
| ③ 去 AI 味 | 按 `de-ai-rules.md` 逐条过，守住改写边界（只改表达、不改事实和确定性） | `lint_x_post.py` 的 W9 / W15 / W16 / W17 清零或能说明保留理由 |
| ④ 排版 | 分段、列表、加粗小标题、配图位置（图紧跟它证明的文字）；X 稿跑 `lint_x_post.py`，公众号稿跑对应排版检查 | E 类错误为 0，W14 清零 |

## 每轮结束

- 记改后字数，交付时写「字数：改前 N → 改后 M」。
- 重新生成派生稿（X长文.md / html / txt 或公众号 HTML），再跑一遍检查与图序核对。
- 交付说明里列出：改了哪些段、新增或删掉的事实与图、仍未核实的条目。
